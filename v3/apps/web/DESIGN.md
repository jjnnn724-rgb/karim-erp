# ليل الياقوت — نظام تصميم Karim ERP React

## النطاق
هذه الهوية تخص واجهة React تحت `/v3`، ولا تغيّر أصول الواجهة القديمة أو عقود API أو صلاحيات المستخدمين. تُطوّر محليًا بلا نشر أو رفع كود. HeroUI 3.2.7 أساس تدريجي للمكونات لا قالبًا جاهزًا يُفرض على العمليات.

## الهوية
واجهة تحريرية مؤسسية لمديري المطاعم وفرق المحاسبة والمخزون والموارد البشرية؛ واضحة، دقيقة، وهادئة. الكانفس عاجي دافئ والأسطح فاتحة، والعمود الجانبي ليلي، والياقوت لون الإجراء الأساسي. الشامبانيا للتفاصيل والعناوين الدقيقة والتركيز، وليس خلفية متكررة للبيانات. النجاح أخضر دلالي منفصل عن التحذير، والخطأ أحمر، والمعلومات أزرق. في الوضع الداكن تُستبدل البدائيات دون تغيير أسماء الدلالات.

## الرموز والخطوط
مصدر الرموز `src/styles.css`. المكونات تقرأ `--erp-*` أو أدوات Tailwind المرتبطة بها، ولا تحمل قيمًا لونية خامًا. طبقة HeroUI تربط `--accent` و`--surface` و`--field-*` بالرموز نفسها. تُعاد الدلالات في `.dark` أيضًا حتى يعمل المعرض الداكن المتداخل.

العناوين العربية والنصوص IBM Plex Sans Arabic، والأرقام IBM Plex Mono بجدولة واتجاه LTR معزول. الخطوط مضمّنة محليًا؛ لا حاجة إلى Google Fonts أو اتصال خارجي. التسلسل: عنوان صفحة 30px، عنوان كبير 22px، عنوان مكون 16px، نص 14px، نص مساعد 13px، تعليق 12px. الزوايا: 6 / 10 / 16 / 20 / 24px، ومسافات أساسية 4 / 8 / 12 / 16 / 20 / 24 / 32px.

## المكونات
`src/ui/Button.tsx` يستخدم مولّد أنماط HeroUI الرسمي `buttonVariants` على زر HTML أصلي للحفاظ على كامل عقد `value` وevents وrefs و`aria-busy` وتعطيل التحميل. هذا اختيار توافق مقصود وليس زرًا مقلدًا.

`Input` و`Card` و`Badge` تستخدم مكونات HeroUI React؛ بطاقة ERP تحافظ على `section` ومراتب العناوين عبر `render`، وأوسمة الحالة تحتفظ بالنص والنقطة وقيمة الحالة غير المعروفة. `definedProps` يحذف فقط القيم `undefined` عند عبور props الأصلية إلى عقود React Aria الصارمة، دون تعطيل strict TypeScript. المكونات المتخصصة كالجداول الافتراضية والحوار والاختيارات تحتفظ بتطبيقها الحالي لتجنب هجرة شاملة عالية المخاطر.

`components/TableState` يُعيد استخدام البطاقة نفسها، و`PageHeader` مصدر موحّد لعناوين الشاشات. `StatCard` يقدم رقمًا واضحًا واتجاهًا نصيًا ولونيًا. التفاصيل الخاصة بالإطار والرئيسية والدخول في ملفات CSS مستقلة ملاصقة لها.

## التفاعل والإتاحة
RTL أولًا: `inline/block` و`start/end` بدل الإزاحات الفيزيائية. القائمة الجانبية قابلة للطي والتمرير والمظهر المضغوط. البحث يحتفظ باختصار Ctrl/⌘+K. درج الهاتف يدعم Escape وحصر التركيز واستعادته. اللون ليس الدلالة الوحيدة للحالة. حلقات التركيز ظاهرة، وتقليل الحركة يحترم `prefers-reduced-motion`. الحركة الاعتيادية 120–260ms ولا تُستخدم لطمس حالة البيانات.

## البيانات والحالات
لا مؤشرات ملفقة ولا ادعاء اتصال أو صحة خادم دون مصدر. الرئيسية تحتفظ بالمصادر القائمة وبصلاحيات كل دور وبحالات التحميل والخطأ والفراغ وفشل بعض المصادر. معرض `/v3/design` يحتوي أمثلة توضيحية معلنة، وليس بيانات منشأة.

## التشغيل محليًا
البناء من هذا المجلد: `node node_modules/vite/bin/vite.js build --configLoader runner`. فحص الأنواع: `node node_modules/typescript/bin/tsc --noEmit -p tsconfig.json`. الاختبارات: `node node_modules/vitest/vitest.mjs run --maxWorkers=2 --configLoader runner`. خيار `runner` يتجنب مشكلة وصول محمّل esbuild إلى مجلدات المستخدم العليا في بيئة Windows الحالية؛ لا يتطلب تغيير سياسة PowerShell.

للتشغيل مع بيانات حقيقية، استخدم خادم المشروع المعتاد مع إعدادات `/v3` الحالية. معاينة Vite الثابتة ليست خادم ERP ولا قاعدة بيانات.
