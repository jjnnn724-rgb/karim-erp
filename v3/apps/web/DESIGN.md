# هوية KARIM — نظام تصميم Karim ERP React

## النطاق

هذه الهوية تخص واجهة React تحت `/v3`، ولا تغيّر أصول الواجهة القديمة أو عقود API أو
صلاحيات المستخدمين. تُطوّر محليًا بلا نشر أو رفع كود. HeroUI 3.2.7 أساس تدريجي
للمكونات لا قالبًا جاهزًا يُفرض على العمليات.

## الهوية

واجهة تشغيلية مؤسسية لمديري المطاعم وفرق الكاشير والمحاسبة والمخزون والموارد البشرية:
كحلي عميق (`#102A43`) وتركواز للإجراء (`#0F766E`) فوق كانفس بارد (`#F3F6FA`) وأسطح
بيضاء (`#FFFFFF`)، وحبر كحلي (`#172B3B`). الأخضر (`#16834A`) للنجاح، والأزرق للمعلومات.
العمود الجانبي كحلي داكن (`#102A43`) وأكسنتُه تركوازي مضيء (`#33BFB1`). في الوضع الداكن
تُستبدل البدائيات بكحلي عميق (`#0C1722`) وتركوازي واضح (`#53D3C5`) دون تغيير أسماء الدلالات.

**ممنوع صراحةً:** التدرّجات الزخرفية، الزجاج (`backdrop-filter`)، الـHero، «KPI
العملاقة»، وحركة تعطّل قراءة البيانات.

## الرموز — ثلاث طبقات

مصدر الرموز `src/styles.css`، والبنية ثلاث طبقات لا تُخترق:

1. **البدائيات** `--erp-c-*` — لون خام بصيغة OKLCH في `:root` و`.dark`. إحداثيات
   OKLCH إدراكية (L للضوء، C للتشبّع، H للدرجة) فتُبنى السلالم بتغيير L وحده؛
   والقيم الحالية تعود إلى HEX العقد بدقة (يتحقق منها الاختبار).
2. **الدلالات** `--erp-*` — الاسم بالوظيفة لا باللون (`--erp-ink` لا `--erp-black`)،
   وتشير إلى البدائيات، فيبدّل الوضع الداكن البدائيات فقط.
3. **الرابط** `@theme inline` — يمنح تيلويند أدوات (`bg-surface`، `text-ink`،
   `font-sans`، `rounded-lg`) تشير إلى الدلالات؛ **لا قيمة لونية خام فيه**، لأنها
   تكسر تبديل الوضع.

المكونات تقرأ `--erp-*` أو أدوات Tailwind المرتبطة بها، ولا تحمل قيمًا خامًا. طبقة
HeroUI تربط `--accent` و`--surface` و`--field-*` بالرموز نفسها.

**حدّ الحقل ≠ الفاصل:** `--erp-field-border` (`#718594` نهارًا، `#648294` ليلًا)
مخصّص لحدود المكوّنات ليحقق WCAG 1.4.11 (3:1)، و`--erp-hairline` (`#DCE5EC`)
للفواصل الزخرفية فقط. `--field-border` و`--input` تقرأ حدّ المكوّن.

**النص الثانوي:** `--erp-muted` = `#596E80` (≥ 4.5:1 على الكانفس والورق)، و
`--erp-faint` = `#526A7A` للتعليقات الأصغر. لا رماديّ «خفيف» يفشل AA.

**الأسماء التاريخية** `brass`/`copper` محفوظة كمرادفات للتوافق مع الشاشات القائمة:
`brass` = تركواز الإجراء، `copper` = أزرق المعلومات.

تستخدم شاشات V3 وقوالب تقاريرها المطبوعة الهوية نفسها: رؤوس كحلية، وإبراز تركوازي،
وحدود باردة؛ وتظل ألوان النجاح والتحذير والخطر مخصصة لدلالات الحالات.

## الخطوط

Tajawal للنصوص والعناوين، مستضاف محليًا (8 ملفات woff2: 400/500/700/800 × مجموعتي
يونيكود عربي/لاتيني) عبر `@font-face` في `styles.css` — بلا Google Fonts وبلا CDN.
`Inter` في السلسلة الاحتياطية للاتيني بلا تضمين (لا ملفات في المستودع)؛ إضافته
= إسقاط ملفات woff2 فقط. الأرقام IBM Plex Mono بجدولة `tabular-nums` واتجاه معزول
(`.erp-numeric`).

التسلسل: عنوان صفحة 30px، عنوان كبير 22px، عنوان مكون 16px، نص 14px، نص مساعد 13px،
تعليق 12px. الزوايا: 6 / 10 / 16 / 20 / 24px، والمسافات على شبكة 4px:
4 / 8 / 12 / 16 / 20 / 24 / 32px.

## المكونات

عقد المكتبة كاملًا (الجرد، متى تستخدم كل مكوّن، قائمة إضافة مكوّن جديد) في
`COMPONENTS.md`. `src/ui/Button.tsx` يستخدم مولّد أنماط HeroUI الرسمي
`buttonVariants` على زر HTML أصلي للحفاظ على كامل عقد `value` وevents وrefs
و`aria-busy` وتعطيل التحميل، مع تجاوزات ERP مسطّحة (بلا تدرّج). `Input` و`Card`
و`Badge` تستخدم مكونات HeroUI React؛ بطاقة ERP تحافظ على `section` ومراتب
العناوين عبر `render`، وأوسمة الحالة تحتفظ بالنص والنقطة وقيمة الحالة غير
المعروفة. `definedProps` يحذف فقط القيم `undefined` عند عبور props الأصلية إلى
عقود React Aria الصارمة.

`Alert` هو الرسالة السطرية الدائمة (خطأ حفظ، تحذير إعداد، نجاح مزامنة) بنبرات
أربع و`role` تلقائي؛ و`Toast` للحظي العابر فقط. الظلال أدوات تيلويند
(`shadow-card`/`shadow-pop`/`shadow-drawer`) تقرأ `--erp-shadow-*` فتتبدّل مع
الوضع الداكن.

`components/TableState` يُعيد استخدام البطاقة نفسها، و`PageHeader` مصدر موحّد لعناوين
الشاشات، و`StatCard` رقم واضح مع اتجاه نصي ولوني. التفاصيل الخاصة بالإطار والرئيسية
والدخول في ملفات CSS مستقلة ملاصقة لها.

## التفاعل والإتاحة

RTL أولًا: `inline/block` و`start/end` بدل الإزاحات الفيزيائية (يمنعه
`src/rtl.test.ts`). بوابة الدخول: النموذج أول عنصر في DOM (ترتيب لوحة المفاتيح)
وأول عمود بصريًا على يمين RTL، ولوحة الهوية على اليسار بلا زخرفة (بلا حلقات أو
تدرّج)، ومع الهاتف شريط هوية قصير أعلى النموذج. القائمة الجانبية قابلة للطي والتمرير
والمظهر المضغوط. البحث يحتفظ باختصار Ctrl/⌘+K. درج الهاتف يدعم Escape وحصر التركيز
واستعادته. اللون ليس الدلالة الوحيدة للحالة. حلقات التركيز ظاهرة على تركواز الإجراء
(2px)، وتقليل الحركة يحترم `prefers-reduced-motion`. الحركة الاعتيادية 120–260ms ولا
تُستخدم لطمس حالة البيانات.

الوصول بوابة لا تحسين: كل زوج نص/خلفية ≥ 4.5:1، وحدود المكوّنات ≥ 3:1، و`axe`
بلا مخالفات critical/serious على بوابتي سطح المكتب والهاتف.

## الحراس الآليون

`src/design-tokens.test.ts` يثبّت الهوية من القيم نفسها: تكافؤ البدائيات بين الوضعين،
عودة OKLCH إلى HEX العقد، تباين AA لكل زوج مستعمل، منع القيم الخام في `@theme`، منع
التدرّج والزجاج في الرموز وأدوات المكوّنات، منع عودة الخط القديم أو بقاء ملف خط ميت،
وشبكة المسافات والزوايا. أي تعديل على الهوية يمرّ من هذا الملف أولًا.

`src/ui/design-system.test.ts` يحرس المكتبة نفسها: لكل مكوّن اختبار شقيق، و`index.ts`
يصدّر كل مكوّن، ولا لون خام/أداة اتجاه فيزيائية/اسم هوية قديم داخل `src/ui`.

## البيانات والحالات

لا مؤشرات ملفقة ولا ادعاء اتصال أو صحة خادم دون مصدر. الرئيسية تحتفظ بالمصادر القائمة
وبصلاحيات كل دور وبحالات التحميل والخطأ والفراغ وفشل بعض المصادر. معرض `/v3/design`
يحتوي أمثلة توضيحية معلنة، وليس بيانات منشأة.

## التشغيل محليًا

البناء: `pnpm --filter @karim/web build`. فحص الأنواع: `pnpm --dir v3 typecheck`.
الاختبارات: `pnpm --filter @karim/web exec vitest run`. بوابة الوصول العامة:
`pnpm --filter @karim/web run e2e:public`. المزامنة إلى الخادم: `npm run v3:sync`.

للتشغيل مع بيانات حقيقية، استخدم خادم المشروع المعتاد مع إعدادات `/v3` الحالية.
معاينة Vite الثابتة ليست خادم ERP ولا قاعدة بيانات.
