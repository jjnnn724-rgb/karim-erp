# مكتبة مكوّنات KARIM — العقد

مرجع التشغيل لمكوّنات `src/ui/`. الهوية (ألوان/خطوط/رموز) في `DESIGN.md`؛ هذا
الملف يجيب على سؤال واحد: **أي مكوّن أستخدم، وبأي عقد، وكيف أضيف واحدًا؟**

## القواعد الأربع

1. **استيراد واحد:** `import { Button, Alert } from '../ui'` — لا مسارات داخلية
   (`../ui/Button`) في كود جديد. `ui/icons` وحدة أيقونات لا مكوّن، وتُستورد مباشرة.
2. **رموز فقط:** لا لون خام (`#…`, `rgb()`, `oklch()`) في أي مكوّن. اللون من أداة
   تيلويند مربوطة بالدلالات (`bg-surface`، `text-ink`، `border-hairline`)، فيتبع
   الوضع الداكن تلقائيًا. الاستثناء الوحيد المعلن: ثوابت `SignaturePad` الاحتياطية
   لأن Canvas لا يقرأ CSS في كل بيئة.
3. **RTL أولًا:** `ms-/me-/ps-/pe-/start-/end-/text-start` فقط. أدوات فيزيائية
   (`ml-`، `left-`، `text-left`) ممنوعة — يحرسها `design-system.test.ts`.
4. **الإتاحة ليست تحسينًا:** كل مكوّن له ملف اختبار شقيق يفحص axe
   (`expectNoAxeViolations`) ويفحص الحالة التي وُجد لأجلها.

## أي واحد أستخدم؟

| الحالة                         | المكوّن                        | لماذا                                                      |
| ------------------------------ | ----------------------------- | ---------------------------------------------------------- |
| حالة تصنيف قصيرة داخل جدول     | `Badge`                       | نصّ دائم + حدّ بلون النبرة، لا لون وحده                       |
| رسالة تخصّ جزءًا من الصفحة وتبقى | `Alert`                       | `role` تلقائي (alert/status)، عنوان + جسم + إجراء، لا تختفي |
| نتيجة إجراء لحظية              | `Toast`                       | عابر أعلى الشاشة، لا يحمل قرارًا                             |
| لا بيانات أصلًا                   | `EmptyState`                  | يشرح السبب ويقدّم الخطوة التالية                            |
| فشل جلب البيانات               | `ErrorState`                  | ماذا حدث + ماذا يفعل المستخدم + إعادة محاولة               |
| جارٍ التحميل                    | `Skeleton`                    | يحفظ التخطيط بلا قفز                                        |
| إجراء رئيسي واحد في الشاشة     | `Button` variant `primary`    | تركواز الفعل؛ الباقي `secondary`/`ghost`                   |
| إجراء أيقوني                   | `IconButton` بـ`label` إلزامي | التسمية لقارئ الشاشة                                       |
| تأكيد عملية خطرة               | `Dialog`                      | لا `window.confirm`                                         |
| نموذج فرعي طويل على الهاتف     | `Drawer`                      | Escape + حصر تركيز + استعادة                               |

**قاعدة الفصل:** `Alert` ≠ `Toast`. الأول يبقى في مكانه لأن الحالة ما زالت قائمة
(إعداد ناقص، تعذّر حفظ، ملاحظة سياسة)، والثاني يُعلن نتيجة لحظية ثم يزول. لا
تستخدم `Toast` لخطأ يمنع المتابعة، ولا `Alert` لرسالة نجاح تغادر تلقائيًا.

**حدود النبرة:** `warning`/`danger` = `role="alert"` (إعلان فوري)،
`info`/`success` = `role="status"` (إعلان مؤدَّب). لا تعِد تعريف النبرة يدويًا.

## الجداول والمرشّحات

- `DataTable` يفرز محليًا فقط القيم التي يعلنها العمود عبر `sortValue`، وعلى
  الصفوف التي استلمها فقط. مع ترقيم خادمي (`pagination.total > rows.length`)
  لا يظهر الفرز المحلي؛ مرّر `onSortingChange` لتفويضه للخادم، مع `sorting`
  للتحكم في علامة اتجاه الفرز.
- `DataTable` يدعم الشجرة عبر `tree.getSubRows` ونموذج التوسيع في TanStack
  React Table؛ تمرير `manualFiltering`/`manualPagination` يعني أن طبقة الخدمة
  تملك المرشّحات والصفحة، والجدول لا يصفّي أو يقطّع الصفوف محليًا. عند التصدير
  الشجري تُضمّن كل فروع مجموعة الصفحة الحالية حتى لو كانت مطويّة.
- التصدير الافتراضي يستخدم `exportValue` لكل عمود مرئي ويقتصر على الصفوف
  المحمّلة. اسم الزر يوضح «الصفحة الحالية» عند وجود صفحات غير محمّلة. للتصدير
  الكامل من الخادم مرّر `onExport` بدل الاعتماد على بيانات الصفحة.
- لا يظهر عمود في أداة اختيار الأعمدة إلا إذا كان `hideable`. مرّر
  `columnPreferenceKey` ثابتًا وفريدًا لحفظ الاختيار في `localStorage`؛ أضف
  معرّف المستخدم إلى المفتاح إذا كانت التفضيلات خاصة بالحساب. يتعذر الحفظ؟
  يعرض الجدول رسالة حالة ويبقي الاختيار للجلسة الحالية.
- `FilterBar` يجمع نطاق التاريخ والبحث النصي، ويقبل `advancedFilters` لمرشّحات
  المجال و`onReset` لمسحها. استخدم `SearchInput` للنص الحر؛ `Combobox` مخصص
  لاختيار قيمة من خيارات قائمة.
- مزامنة حالة المرشّح مع الرابط مسؤولية المسار: استخدم `validateSearch` وواجهات
  TanStack Router (`useSearch`/`useNavigate`)، ولا تعدّل `history` مباشرة. تبقى
  المرشّحات المحلية محلية ولا تغيّر عقد API ما لم يمررها المسار صراحةً للخادم.
- **قيد شجرة الحسابات:** `/api/v3/accounting/chart` يعيد القائمة كاملة فقط؛ لا
  يقبل ترقيمًا أو مرشّحات، وعقد الحساب لا يتضمن `branch_id`. لذلك تعرض شاشة
  الحسابات خدمة `MOCK` موسومة في الكود تطبق البحث والنوع والمستوى والترقيم
  بالذاكرة على بيانات API الحقيقية، وتُبقي مرشّح الفرع معطّلًا مع شرح السبب.
  هذا بديل مؤقت متوافق مع عقد الخدمة المنتظر، وليس ترقيمًا/ترشيحًا خادميًا فعليًا؛
  يتطلب ذلك دعمًا لاحقًا من الخادم، دون تغيير API ضمن هذه المرحلة.

## الظلال والزوايا والمسافات

- الظلال أدوات: `shadow-card` (سطوح ثابتة) · `shadow-pop` (قوائم منسدلة) ·
  `shadow-drawer` (نوافذ/أدراج). كلها تقرأ `--erp-shadow-*` فتتبدّل ليلًا.
  لا `shadow-[0_…_rgb(…)]` مخصّصًا في مكوّن.
- الزوايا 6/10/16/20/24px، والمسافات على شبكة 4px. لا قيمة عشوائية.
- لا `dark:` في مكوّنات المكتبة: الرمز يتبدّل، والمكوّن لا يعرف الوضع.

## لماذا لا CVA؟

`class-variance-authority` موجودة في التبعيات لكنها غير مستخدمة في `src/ui`.
النمط المعتمد `Record<Variant, string>` + `cn()`، وهو مكافئ وظيفيًا وأقل طبقة:
النبرات هنا مجموعات أدوات ثابتة لا تركيبات بلا حدود، والتوحيد المهم هو **نمط
واحد** في كل المكتبة. تحويل المكتبة إلى CVA بلا حاجة عملية يزيد الحزمة والقراءة.
الاستثناء: `Button` يعتمد مولّد HeroUI الرسمي (`buttonVariants`) لأنه يملك عقد
`value`/events/`aria-busy` جاهزًا.

## إضافة مكوّن — قائمة تحقق

1. `src/ui/<Name>.tsx` مع تعليق رأس يشرح **متى** يُستخدم لا كيف يُبنى.
2. `src/ui/<Name>.test.tsx`: الاختبار السلوكي + `expectNoAxeViolations`.
3. تصدير من `src/ui/index.ts` (المكوّن + أنواع الـprops).
4. قسم في `src/screens/DesignGallery.tsx` (الوضعان + الحالات).
5. سطر في جدول الجرد أعلاه، وتحديث `DESIGN.md` إن مسّت الهوية.
6. تشغيل البوّابات: `vitest run` · `pnpm --dir v3 typecheck` · `build` ·
   `e2e:public` · `e2e:budget`.
7. `CHANGELOG.md` بُند واحد يوضح الفجوة التي سُدّت.

الحارس `src/ui/design-system.test.ts` يفشل تلقائيًا إن نسيت (2) أو (3)، أو أدخلت
لونًا خامًا أو أداة اتجاه فيزيائية أو اسمًا من الهوية القديمة.
