# محرك واتساب — Karim ERP (Baileys، يعمل محليًا)

محرك أتمتة واتساب إنتاجي يعمل **داخل عملية سيرفر karim** (نفس نمط `yarasoft`):
`backend/whatsapp-engine/` + ترحيل `053_wa_engine.sql` + مسارات `/api/whatsapp/*` + صفحة
`واتساب` في الواجهة (مدير/مدير مطعم).

> تنبيه صريح: التشغيل الذاتي المجاني لا يضمن دائمية الخدمة ولا حصانة من قيود
> واتساب. السلوك محافظ (حد إرسال افتراضي 20/دقيقة، بلا رسائل جماعية غير مرغوبة)،
> واحترموا شروط واتساب وخصوصية المستخدمين.

## 1) التثبيت

```powershell
npm install            # يثبت baileys@7.0.0-rc14 (مثبت في package.json)
```

| القرار | السبب |
|---|---|
| `baileys@^7.0.0-rc14` (وليس v6) | v6 يتطلب `git` (اعتماديات github) وغير موجود على الجهاز؛ v7 اعتمادات npm فقط وتم التحقق من عمل الجسر الأصلي على Windows + Node 26 |
| JS وليس TypeScript | المشروع كله JavaScript — نفس الـ conventions |
| جداول `wa_*` في PostgreSQL | بلا SQLite ثانٍ؛ منع الازدواج بقيود UNIQUE |
| داخل عملية السيرفر | نفس نمط المحركات (attendance/yarasoft/oracle) — بلا عمليات إضافية |
| الجلسات في `C:/KarimData/whatsapp-sessions` | خارج الكود وخارج الحزم (لا تُحزم في EXE ولا تُرفع) |

## 2) الإعداد (.env)

```ini
WHATSAPP_ENABLED=false            # فعّله true بعد الجاهزية
WHATSAPP_SESSION_DIR=C:/KarimData/whatsapp-sessions
WHATSAPP_LOG_LEVEL=info
WHATSAPP_RECONNECT_BASE_DELAY=2000
WHATSAPP_RECONNECT_MAX_DELAY=60000
WHATSAPP_MAX_RETRIES=5
WHATSAPP_SEND_TIMEOUT=30000
WHATSAPP_WORKER_INTERVAL=5000
WHATSAPP_MAX_OUTBOUND_PER_MIN=20
WA_SEND_MIN_GAP_MS=3000
WA_SEND_JITTER_MS=2500
WA_WARMUP_SCHEDULE=20,40,80,160,320,640,1000
WA_COLD_CAP_SCHEDULE=5,10,20,40,60,80,100
WA_BULK_DISTINCT_JIDS=8
JWT_REFRESH_DAYS=365
ERP_API_TIMEOUT=8000
```

## 2-مكرر) درع الحظر — أي نمط خطر مرفوض صلبًا (429) قبل الوصول لواتساب
| الرفض | متى |
|---|---|
| `BULK_FROZEN` | نفس النص لأكثر من `WA_BULK_DISTINCT_JIDS` جهات خلال `WA_BULK_WINDOW_MIN` دقيقة — الإرسال الجماعي المتماثل مجمّد نهائيًا (أقوى إشارة حظر) |
| `WARMUP_CAP` | تجاوز السقف اليومي لعمر الجلسة (تهيئة الرقم الجديد تدريجيًا) |
| `COLD_CAP` | أول رسالة لجهات بلا أي سجل تواصل فوق السقف اليومي (يُعفى الرد على وارد) |
| `SENDER_PAUSED` | قاطع الإرسال: إخفاقات متتالية توقف المحرك مؤقتًا بدل القصف أثناء عطل |
الإرسال الفعلي بإيقاع بشري: فجوة دنيا + jitter + مؤشر "يكتب...". الردود على
الرسائل الواردة والتقارير للمديرين المعرّفين هي المسار الآمن الموصى به —
لا بثّ تسويقي بارد إطلاقًا من هذا المحرك.

الإقلاع يفشل سريعًا (`WHATSAPP_CONFIG_INVALID`) عند إعداد حرج غير صالح — لكن
المحرك معطّل افتراضيًا فلا يوقف السيرفر.

## 3) التشغيل

- تلقائي مع خدمة `KarimERP-Server` (boot/stop hooks في `server.js`).
- `POST /api/whatsapp/start` و `/stop` للتحكم اليدوي (swith rate-limit).
- الإيقاف النظيف: `stop()` يلغي المؤقت، يزيل المستمعين، يغلق المقبس.

## 4) الربط (QR / رقم الهاتف)

1. فعّل `WHATSAPP_ENABLED=true` وأعد تشغيل الخدمة.
2. افتح صفحة **واتساب** ← الحالة ← **جلب الرمز** ← امسحه من واتساب الهاتف
   (الأجهزة المرتبطة ← ربط جهاز). الرمز يتحدث كل ~15 ثانية.
3. بديل: **ربط برقم الهاتف** (رمز 8 خانات) إن دعمه الحساب.
4. تحقق من الحالة `CONNECTED` وآخر اتصال ناجح.

## 5) API الإدارة (admin/manager، بعضها admin فقط)

| المسار | الوصف |
|---|---|
| `GET /status` | الحالة + الطوابير + المقاييس |
| `GET /health` | ملخص صحي مختصر |
| `GET /qr` | رمز QR نصًا (يُرسم في المتصفح) |
| `POST /pairing {phone}` | رمز ربط (rate-limit 3/دقيقة) |
| `POST /start` `/stop` | بدء/إيقاف |
| `POST /logout {confirm:LOGOUT}` | خروج admin + مسح الجلسة |
| `POST /send {to, body}` | إرسال عبر الطابور الدائم |
| `POST /send-media {to, kind, url|path, caption}` | إرسال صورة/فيديو/صوت/مستند عبر نفس الطابور ودروع الحماية |
| `GET/POST /templates` | عرض/حفظ القوالب (الحفظ admin) |
| `POST /templates/send {to, name, vars, lang}` | عرض {{1}} + ارسال عبر الطابور (422 عند نقص متغير) |
| `GET/POST /campaigns` | حملات Draft بمستلمين وموافقة consent فقط |
| `POST /campaigns/:id/approve` `/pause` `/cancel` | دورة موافقة وتحكم إداري بالحملة |
| `GET /messages` `GET /outbox` | الوارد/الصادر |
| `GET/POST /chats/:jid/meta` | مساحة عمل المحادثة: تعيين، حالة، أولوية، tags وملاحظة داخلية |
| `GET/POST/DELETE /rules` | قواعد الرد |
| `POST /chats/auto-reply` | تفعيل/تعطيل الرد لكل محادثة |
| `GET/POST/DELETE /managers` | قايمة أرقام الإدارة (تقرير واتساب — admin) |
| `GET/POST /automation` | إعدادات التقرير الليلي والتنبيهات (admin) |
| `POST /automation/test` | إرسال التقرير الليلي الآن (تجربة) |
| `GET /logs` | سجل الأحداث |

لا تُعرض ملفات الجلسة عبر HTTP إطلاقًا. لا تُسجل المفاتيح أو المحتوى الخاص.

### الحملات الآمنة
الحملة لا تبدأ بمجرد إنشائها: يجب أن تكون `draft` ثم يعتمدها admin. لا يرسل
المحرك إلا للمستلمين الذين يرسلون `consent=true`، ويستخدم القوالب والطابور
المحمي بالسقوف والـ pacing الحالي. الإلغاء والإيقاف يوقفان الرسائل pending،
ولا يُنصح باستخدام الحملات للتواصل البارد أو الرسائل غير المطلوبة.

## 6-مكرر) الميديا (v5.0)
- **استقبال**: الصور/الفيديو/الصوت/المستندات تُنزَّل تلقائيًا إلى
  `WHATSAPP_MEDIA_DIR/incoming/YYYY-MM-DD/` (بحد `MEDIA_MAX_SIZE_MB`) وتُسجَّل
  في `wa_inbox` مع رد إقرار عربي تلقائي. الملصقات تُسجَّل بلا رد (مقصود).
- **إرسال**: `POST /send-media` بنفس الطابور الدائم ودروع الحظر الثلاثة
  (BULK_FROZEN/WARMUP_CAP/COLD_CAP) + حد معدل + retry أسي.
- ```powershell
  npx jest tests/whatsapp-media.test.js   # 14 اختبار (كشف/أسماء آمنة/حمولات/حدود)
  ```

## 6) خط الرسائل

`upsert → تحقق JID → تجاهل رسائلنا → تطبيع → wa_processed (idempotent) → حفظ → قواعد → ERP → طابور رد → تدقيق`

- أنواع غير نصية تُسجل `unsupported` بلا رد.
- القواعد: `exact`/`contains`/`command` (عربي+إنجليزي، تطبيع تشكيل/همزات).
- الأوامر المدمجة: `مساعدة`، `ساعات العمل`، `حالة طلب <رقم>` (قراءة فقط: الحالة+الإجمالي).
- الصادر: `pending→sending→sent|failed` + retry أسي مع jitter + حد معدل.

## 7) التقارير المجدولة والتنبيهات (automation.js)

- **التقرير الليلي**: يُدفع تلقائيًا لأرقام الإدارة في `WHATSAPP_DAILY_REPORT_TIME`
  (افتراضي 23:30 بتوقيت الرياض) — مرة واحدة يوميًا (idempotent بتاريخ اليوم).
  يُضبط من صفحة واتساب (إعدادات) أو `POST /automation`، والتجربة بزر
  **تجربة إرسال الآن** (`POST /automation/test`).
- **تنبيهات فورية** (مرة واحدة لكل حدث، تُصفَّر بزوال السبب): انقطاع جهاز
  البصمة، أقسام تنتظر اعتمادًا، فواتير فاشلة اليوم.
- بعد الإقلاع بدقيقتين يعمل فحص أول، ثم كل دقيقة.

## 9) النسخ والاسترداد

- **القاعدة**: زر النسخ في الإعدادات يشمل جداول `wa_*` تلقائيًا.
- **الجلسة**: انسخ `C:/KarimData/whatsapp-sessions` والجهاز متوقف فقط،
  الاستعادة بنفس الشرط. لا ترسل الجلسة عبر أي قناة غير آمنة.
- **تلقائي (v5.1)**: عند كل اتصال ناجح تُنسخ `creds.json` إلى `WHATSAPP_BACKUP_DIR` (آخر 10 نسخ) — الاسترداد: أوقف الخدمة، انسخ أحدث نسخة باسم `creds.json` إلى مجلد الجلسات، شغّل.
- تلف الجلسة: صفحة واتساب ← خروج ومسح ← ربط جديد بالـ QR.

## 10) التشغيل والاستكشاف (OPERATIONS)

| العرض | المعنى | الإجراء |
|---|---|---|
| `QR_REQUIRED` طويلًا | لم يُمسح الرمز | جلب رمز جديد (ينتهي خلال ~دقيقة) |
| `RECONNECTING` متكرر | شبكة متقطعة | تحقق من الإنترنت؛ الفاصل يتوسع تلقائيًا حتى 60ث |
| `LOGGED_OUT` | واتساب أبطل الجلسة | ربط جديد (لا يحاول تلقائيًا — مقصود) |
| `FAILED` عند البدء | إعداد/اعتماديات | راجع سجل السيرفر + `WHATSAPP_*` |
| رسائل `failed` متراكمة | انقطاع طويل | تُعاد تلقائيًا؛ `dead` بعد 5 محاولات (راجع السجل) |
| استهلاك ذاكرة | `GET /health` يعرض `mem` | أعد تشغيل الخدمة إن نما باطراد عبر أيام |

حدود معروفة: Baileys مثبتة `7.0.0-rc14` (مرشحة إصدار — راقب المستقر)؛ حزمة
الـ EXE تستهدف `node18` بينما Baileys 7 تتطلب `node>=20` + جسر أصلي — بناء
الـ EXE يحتاج مراجعة الهدف قبل الشحن (لم يُغيَّر في هذا التسليم)؛ الإرسال
"مقبول/مُرسل" وليس "تسليمًا مضمونًا"؛ الوسائط (صور/صوت) تُسجل بلا معالجة.
