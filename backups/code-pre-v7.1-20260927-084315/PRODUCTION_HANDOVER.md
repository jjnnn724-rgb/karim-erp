# محضر تسليم إنتاجي — مطاعم الشرفة العالمية

## النسخة

الإصدار الحالي هو `3.1.0`. تم بناء نسخة Windows x64 بمثبت NSIS باسم `Al-Shorfa-International-Restaurants-Setup-3.1.0.exe`.

## الإصلاحات النهائية

تم إصلاح مسار بيع الكاشير بعد اكتشاف أن استعلام الوصفة كان يقرأ `rvi.product_id` من جدول لا يحتوي على هذا العمود. أصبح الاستعلام يقرأ `rv.product_id` من جدول إصدارات الوصفات، وتم اختبار بيع فعلي نتج عنه فاتورة وسجل طباعة وقيد إيراد.

تم إصلاح عدم ظهور إيرادات POS في الإيراد العام وبطاقات الأقسام. كان السبب أن الواجهة تحمل أول صفحة فقط من مسار الإيرادات بحد افتراضي 50 سجلًا، بينما حسابات اللوحة تعتمد على البيانات المحملة في الواجهة. أصبح `apiList` يقرأ جميع الصفحات من PostgreSQL، وتم تصحيح جمع المبالغ الرقمية وإضافة إصدار للسكريبت لمنع استخدام نسخة قديمة من المتصفح.

تم تضمين وضع خدمة Windows headless عبر WinSW باسم `AlShorfaERP`. تسجل الخدمة وتبدأ تلقائيًا مع Windows، وتشغل PostgreSQL Portable وخادم Express بدون فتح نافذة Electron، مع إعادة التشغيل عند الفشل وسجلات قابلة للتدوير وإزالة آمنة عند إلغاء التثبيت.

## الملفات

يتضمن التسليم مثبت Windows، أرشيف المشروع الكامل المصحح، ملف SHA-256، هذا التقرير، وتوثيق التوقيع الرسمي.

أرشيف المشروع لا يتضمن `node_modules` أو بيانات PostgreSQL المحلية أو مجلدات البناء المؤقتة، لكنه يتضمن الشفرة المصدرية وملفات الإعداد وPostgreSQL Portable وملفات الخدمة اللازمة لإعادة البناء والتشغيل.

## SmartScreen

المثبت الحالي غير موقّع بشهادة Code Signing خاصة بالناشر لعدم توفر الشهادة داخل بيئة البناء. لم تتم إضافة أي تجاوز أو تعطيل لـ SmartScreen. لتقليل التحذيرات بالطريقة الإنتاجية الصحيحة، يجب توقيع المثبت والتطبيق بشهادة مرتبطة بالاسم القانوني للناشر باستخدام المتغيرين `CSC_LINK` و`CSC_KEY_PASSWORD` كما هو موضح في `CODE_SIGNING.md`.

## ملاحظة التحقق النهائي

تم التحقق من بناء ملف EXE ومحتوياته واختباره بنيويًا، كما تم تشغيل اختبارات النظام والخادم وقاعدة البيانات. يجب تنفيذ تجربة التثبيت الأخيرة على جهاز Windows حقيقي للتحقق من نافذة المثبت وظهور خدمة `AlShorfaERP` داخل `services.msc`، لأن بيئة البناء الحالية ليست Windows أصليًا.
