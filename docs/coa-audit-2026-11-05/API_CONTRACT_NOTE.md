# 17. API_CONTRACT_NOTE.md — عقد الـ API لـ frontend-v3 (React) موازاةً لـ Phase 2

## القاعدة الذهبية
**Phase 2 Additive لا يغيّر شكل أي استجابة API قائمة.** الـ frontend-v3 يُبنى على نفس العقد الحالي بأمان.

## قبل Phase 3 (سلوك اليوم)
- `GET /api/accounting/chart` يرجع قائمة مسطحة `[{code,name_ar,name_en,type,parent_code,is_postable,is_active}]` — **لن نحذف/نعيد تسمية/نغيّر نوع أي حقل**. أي توسعة (normal_balance, fs_classification…) ستكون **إضافة حقول فقط**، ولا يُفرض على frontend-v3 استهلاكها فورًا.
- كل مسارات `/api/accounting/*` كما هي؛ `account_mapping` غير مكشوف عبر API (داخلي حتى إشعار آخر).
- `134/135` لا يُضيفان أي endpoint ولا يغيّران أي payload.

## قواعد التوسعة المستقبلية (ملزمة من الآن)
1. حقول جديدة = **اختيارية دائمًا**؛ أي حقل جديد يوثَّق في CHANGELOG + CONTRACT.md مع مثال.
2. لا إعادة تسمية/حذف/تغيير نوع حقل أبدًا — التغيير = إيقاف تدريجي (deprecation) لنسختين على الأقل.
3. أي endpoint جديد يُذكر في `CONTRACT.md` (الملف المرجعي للعقد في المستودع) قبل الدمج.
4. frontend-v3 يكتشف الحقول الاختيارية ديناميكيًا (لا افتراض وجودها)؛ شاشات الجديدة (Command Center) ستُبنى على عقد موثّق حينها.
5. في كل مرحلة، جدول:
| الحقل/الـendpoint | المرحلة | التغيير | توافق العقد |
|---|---|---|---|
| chart[].normal_balance | Phase 2 (DB) / Phase 3 (API) | إضافي اختياري | متوافق |
| chart[].fs_classification | Phase 3 | اختياري | متوافق |
| GET /accounting/accounts/:code (تفاصيل) | Phase 4/5 | جديد | لا يكسر |
| account_mapping.* | Phase 4 | داخلي → اختياري مكشوف للأدمن | منفصل |
| posting_failures list | Phase 3 | جديد للأدمن | لا يكسر |

## ما يجب على frontend-v3 تجنبه
- الاعتماد على ترتيب الحقول — استخدم الأسماء.
- افتراض `id` معين أو فواصل أرقام.
- افتراض أن حساب مُعطّل لن يرجع في `/chart` — اليوم يرجع الكل؛ الفلترة بالواجهة.
- استخدام `is_postable` لمنطق ترحيل — هو لعرض "قابل للترحيل" فقط.
- أي تكامل مباشر مع قاعدة البيانات — **API فقط** (قاعدة: React ↔ API ↔ PostgreSQL).

## اللغة والتعريب
الاستجابات ثنائية (name_ar مطلوب، name_en اختياري تاريخيًا — قد تكون NULL لبعض الحسابات القديمة) — frontend-v3 يعرض fallback: name_en ?? '-' أو العكس.
