# 4. POSTGRESQL_DATA_OWNERSHIP.md — الملكية الحصرية لـ PostgreSQL (READ-ONLY)

## 1. من يملك البيانات؟
**PostgreSQL المحلي هو مصدر الحقيقة المحاسبي الواحد.** الأدلة:
1. النظام **لا يقلع** دون PostgreSQL (`backend/startup.js`: فحص `SHOW server_version` + `SELECT 1` → `BOOT_VALIDATION_FAILED`).
2. كل القيود والشجرة والفترات والتقارير تُخزّن وتُستعلم من `karim_erp` — لا توجد نسخة محاسبية "صامتة" في Oracle أو على الشبكة.
3. `docker-compose.yml` موجود لكن Docker غير مثبت — التشغيل الفعلي هو **خدمة Windows الأصلية `postgresql-x64-18` RUNNING على 5432** (وليس container).
4. `.env`: `DB_MODE=system`، `DB_USER=karim_app` (دور التطبيق) — فصل جيد عن `postgres` الإداري (مموّه).
5. نسخ احتياطية: `database/scripts/backup.js` + `KARIM_BACKUP_*` (احتفاظ + GPG اختياري + نسخ مرآة) — موجودة كآلية، لكن **اختبار استرجاع فعلي غير موثق في هذه الجلسة** (لم يُنفذ).

## 2. ما ليس مصدرًا للحقيقة (مهم)
- **YaraSoft/Oracle**: مصدر تشغيلي للمبيعات التاريخية والحيّة — يُقرأ فقط (انظر 5). نتيجته النهائية المقبولة محاسبيًا تمر عبر جسر `gl-bridge` إلى PostgreSQL بقيد موثق.
- جداول `ora_*` داخل `karim_erp` نفسها هي **مرآة نسخ (read-only copies)** للتدقيق/المقارنة — وليست مصدر ترحيل. وجودها داخل PG لا يجعلها ملكًا محاسبيًا؛ هي لقطات للقراءة.
- مشاركة `C:/HorusData/Yarasoft` ملفات — إدخال خام للاستيراد، لا تُقرأ إلا بواسطة المحرك.

## 3. هل تعمل المحاسبة مع انقطاع Oracle؟ — نعم، باستثناء الإيراد اللحظي
| الوظيفة | بدون Oracle | بدون PostgreSQL |
|---|---|---|
| الترحيل/التوازن/القيود | ✅ نعم (داخلي بحت) | ❌ النظام كله يتوقف |
| دفتر العام/الميزانية/الدخل | ✅ نعم | ❌ |
| الفترات والإقفال | ✅ نعم | ❌ |
| التسويات والعهد والإهلاك | ✅ نعم | ❌ |
| ZATCA | معطّل افتراضيًا (`ZATCA_ENABLED=false`) | ❌ |
| تقارير الكاشير الحيّة من Oracle | 503 / آخر لقطة stale ≤15 د (documented `yara-reports`) | ❌ |
| **ترحيل إيراد مبيعات الكاشير الجديد** | ❌ لا يصل للدفتر (لا كجسر ولا كمبيعات محلية — `pos_orders` فارغ) | ❌ |

## 4. الحصانة القاعدية (تحقق حي سابق)
- 147+ فهرس مهاجرة؛ 29 trigger؛ منهم المحاسبي: `trg_journal_posted_balance` (DEFERRABLE)، `trg_journal_posted_identity`، `trg_stamp_branch_journal_entries` (و+10 حقول branch أخرى)، `trg_pos_*` المتسلسلة.
- Constraints: `journal_entries_status_check`, `uq_journal_source` (NULLS NOT DISTINCT), `ck_journal_line_side`, `accounting_periods_period_check ^YYYY-MM$`, `cost_centers_code_check`, الفروع تسم ختم branch.
- NUMERIC(14,2) للأموال — **لا FLOAT/DOUBLE** في الدفتر. ✅ مطابق للقاعدة الذهبية.

## 5. الفجوات التي تمنع "PostgreSQL المصدر الوحيد الكامل" حاليًا
1. **سلسلة الإيراد التشغيلي** تحتاج Oracle لملء `revenues` (الاستيراد الدوري كل دقيقة) — بدونها الدفتر يظل صحيحًا لكنه **ناقص الصفوف الجديدة**؛ النظام "يعمل" لكن لا يسجل بيع الكاشير. هذا ليس اعتماد حسابي، بل **اعتماد بياني**.
2. **الاعتماديات على ora_***: المقارنة `finance-routes.js:668-735` (oracleByMonth) تتعطل بدون Oracle — تقرير مقارنة فقط، وليس شرطًا للمحاسبة.
3. **لا طابور "قيد فاشل" إلزامي للعمليات الداخلية** — الفشل يُسجَّل تحذيرًا في بعض المسارات ويُفقد أثريًا بدون متابعة مضمونة (يحتاج جدول `posting_failures` أو مسار outbox).
4. **الاسترجاع الفعلي (restore drill) غير موثق** في هذه الجلسة — خطر تشغيلي (غير محاسبي تصميمًا).
5. **الحذف الصلب المسموح على posted** (095) — يخالف "سجل تدقيق غير قابل للمسح"؛ يجب تحويله إلى void-only في الخطة.

## 6. الحكم (للإدارة)
- القاعدة: PostgreSQL = مصدر الحقيقة. ✅ مُثبت تصميميًا وعمليًا للوظائف المحاسبية الداخلية.
- المطلوب لإتمام الملكية: إغلاق سلسلة الإيراد (قرار: قسر الاستيراد عبر بوابة مصالحة إلزامية، أو اعتماد POS محلي كمسار أساسي مع جسر Yara اختياري)، ومنع الحذف الصلب، وطابور قيود فاشلة، واختبار استرجاع موثق.
