# 9. GLOBAL_COA_TARGET_DESIGN.md — التصميم المستهدف لشجرة حسابات عالمية (مسودة للاعتماد — لم تُطبّق)

> هذا تصميم **مرجعي للاعتماد** — لا يغيّر أي كود أو قاعدة قبل موافقة صريحة (المرحلة 1).
> القاعدة الذهبية: **لا حذف، لا إعادة ترقيم، لا تعديل معنى حساب قائم. كل تطوير إضافي (Additive) فقط.**

## 1. الفلسفة (5 أهداف)
1. وضوح التصنيف · 2. سهولة الوصول · 3. منع الخطأ قبل الحدوث · 4. مرونة التوسع · 5. اتصال مباشر بالقوائم/التحليل.
لا شجرة ضخمة شكلية — كل حساب له غرض محاسبي واضح وطبيعة وأثر على التقارير.

## 2. المبادئ الملزمة
- **IFRS-aligned** لا "مدّعى IFRS": التصنيف يُثبت بقواعد + mapping + اختبارات (لا بالأسماء).
- الفصل بين: **الحساب المحاسبي ↔ البعد التحليلي (مركز تكلفة/فرع/مشروع) ↔ الكيان القانوني**.
- لا آلاف حسابات لأجل كل فرع/منتج — الأبعاد تُسند على السطور (`cost_center_code`, `branch_id`) لا على الحسابات.
- `8000` (إن اعتمد) للحسابات الرقابية/الوسيطة **فقط مع حوكمة**: مالك + سياسة تصفير + تقرير رصيد/انحراف + تنبيه — لا لإخفاء الأخطاء.
- السعودية/VAT/ZATCA = **إعدادات قابلة للتكوين** (tax_config / ZATCA settings) وليست جزءًا من بنية الحساب.
- Multi-company / Multi-currency = **غير موجود الآن**؛ التصميم لا يمنعه ولا يفترضة (لا `company_id` قبل دراسة الأثر — تجميد).

## 3. البنية المستهدفة — "Karim Global CoA" (8 أقسام، توافقية مع القائم)
**الإستراتيجية: اعتماد الأقسام الثمانية المطلوبة مع الحفاظ على أكواد القائمة (ترجمة + توسعة لا هدم).**

| القسم | المعنى | الحالة اليوم | المعاملة المستهدفة |
|---|---|---|---|
| **1000 Assets** | أصول | موجود (`1xxx`) | إبقاء + توحيد التصنيف `asset` + فصل متداول/غير متداول صراحةً عبر أعمدة mapping |
| **2000 Liabilities** | التزامات | موجود (`2xxx`) | نفسه + فصل متداول/غير متداول + ST/LT |
| **3000 Equity** | حقوق ملكية | موجود (`3xxx`) | نفسه + SOCE feed |
| **4000 Revenue** | إيرادات | موجود (`4xxx`) | نفسه + خصومات/مردودات كحسابات contra-revenue صريحة (مقترحة: `4910/4920`) |
| **5000 Cost of Revenue** | تكلفة الإيراد | موجود (`5xxx`) | ربط ترحيل فعلي بـ 5120..5400 تدريجيًا (لا يكسر المعروض اليوم) |
| **6000 Operating Expenses** | مصاريف تشغيلية | موجود (`6xxx`) | إبقاء 6100–6900 وإضافة: ترحيل منافع الموظفين/إهلاك/اتصالات إلى الحسابات التفصيلية الموجودة |
| **7000 Other Income & Expenses** | أخرى | **غير موجودة** | **إضافة**: `7100` إيرادات استثمارية/أرباح فروق عملة · `7200` أرباح بيع أصول · `7300` خسائر بيع أصول · `7400` تكاليف تمويل · `7500` فروق عملة (ربح/خسارة) · `7600` خسائر ائتمانية متوقعة · `7700` بنود غير متكررة — كلها قابلة للترحيل، mapping إلى IS بند "أخرى" |
| **8000 Control/Clearing** | رقابية وسيطة | **غير موجودة** (وسيط ضمني `1150`) | **إضافة(تحتاج قرار اعتماد)**: `8100` وسيط تسوية POS/Mada (يستبدل 1020؟ لا — يُبقى 1020 كحساب تشغيلي، 8100 للتسويات المعلقة) · `8200` وسيط تحويلات بينية · `8210` وسيط فروق جرد — **مع `is_suspense=true` + مالك + حد رصيد + تنبيه إقفال** — خلاف ذلك لا يُعتمد |

## 4. ميتاداتا الحساب المستهدفة (إضافية، كلها nullable/Default غير كاسر)
```
account_subtype VARCHAR        -- e.g. cash, bank, ar, inventory, vat_input...
normal_balance  VARCHAR(6)     -- debit|credit  (يُستنتج أول مرة من type، ثم يُثبّت)
fs_classification VARCHAR      -- e.g. BS.CA / BS.NCA / IS.REV / IS.COS / IS.OPEX / EQUITY / CF.OPERATING
cash_flow_class VARCHAR(20)    -- operating|investing|financing|none
tax_category    VARCHAR(30)    -- vat_input|vat_output|exempt|zero_rated|non_vat
is_control      BOOLEAN        -- حساب رقابي (AR/AP/…) — لا يُرحل مباشرًا إن كان control حقيقي
is_suspense     BOOLEAN        -- وسيط — يتطلب تصفية وإقفال
is_reconcilable BOOLEAN        -- يحتاج تسوية دورية (بنوك/عهد/ضريبة)
accounting_policy_ref TEXT     -- مرجع سياسة محاسبية
effective_from DATE / effective_to DATE
created_by / updated_by
```
+ **جدول** `account_fs_mapping(statement_code, section, line, account_code, side, sign, priority, valid_from, valid_to)` — التصنيف لكل قائمة مستقلة (البرومبت §9: فصل التصنيف الشجري عن تصنيف القائمة).
+ **جدول** `account_mapping(module, operation, account_role, account_code, active)` — بديل الثوابت المتناثرة (ترحيل تدريجي، لا يكسر شيئًا).
+ منع الدورة/الذاتية (trigger) + منع تغيير `type`/`normal_balance` إن كان للحساب حركات `posted` (إلا عبر إجراء موثّق ثنائي).

## 5. نموذج الاستخدام (كيف يقرأ المحاسب النظام)
- الشجرة تعرض: الكود · الاسم (عربي/إنجليزي) · الطبيعة · الرصيد الحالي · #قيود · حالة الاستخدام · آخر حركة.
- تفاصيل الحساب: الأب/الأبناء · التصنيف المالي · مركز/فرع · المصادر (POS/Yara/يدوي/رواتب…) · سجل تغييرات.
- أي حساب ممنوع ترحيله ← رسالة تخبر: **لماذا مُنع** (قاعدة: ترحيل على تجميعي)، **والبديل الصحيح** (حساب تشغيلي تحته)، **وأثره على التقارير** — لا رسالة عامة.

## 6. الفصل عن الأبعاد (لا تخلط)
- الفرع/المركز/المشروع/القناة/الوحدة التجارية = أبعاد على السطر + ترويسة القيد — **ليست حسابات**.
- الشجرة تتوسع رأسيًا (مستوى 3 تجميعي ← مستوى 4 تشغيلي) فقط عند حاجة محاسبية، لا لأجل بُعد تحليلي.

## 7. السعودية كإعدادات (لا كبِنية)
- VAT (15%)، ZATCA Phase 2، GOSI، Zakat — كلها في `tax_config`/إعدادات ZATCA + فئات ضريبية على الحساب — **ليست codes إلزامية**؛ النظام يعمل لشركة خارج السعودية بتغيير الإعدادات.

## 8. ما لن يحدث (ضمان صفري للمؤسسة القديمة)
لا إعادة تسمية/ترميز تاريخي، لا حذف، لا نقل مستخدم، لا تغيير رصيد — أي حساب "خاطئ التصنيف" يُصحح عبر mapping جديد لا بمسح التاريخ. الأرصدة الافتتاحية تُبنى كتسوية فتح موثقة بـ `source_type='opening'` (موجود نمطه في 094 فقط للمخزون — يُعمم للمحاسبي في Phase 4).
