# خطة نافذة تطبيق الإنتاج 134 → 143 (karim_erp)

- **التاريخ:** 2026-11-07
- **الحالة:** **معتمدة من المالك** لنافذة **2026-11-07 23:00** (UTC+3) — لم
  يُطبَّق أي شيء على الإنتاج بعد.
- **التنفيذ التشغيلي:** `PRODUCTION_APPLY_RUNBOOK.md` (تطبيق) +
  `PRODUCTION_ROLLBACK_RUNBOOK.md` (تراجع).
- **الشرط الحاكم:** لا قيود تُرحَّل ولا مستخدمون على النظام أثناء التطبيق.

## 0) العقبة الوحيدة قبل البدء: الترحيل التلقائي ما زال نشطًا

فحص الإنتاج (قراءة PostgreSQL فقط) في 2026-11-07 00:35 (محلي):

```
آخر 120 دقيقة: 75 قيدًا، كلها source_type=yarasoft_revenue
آخر قيد: JE-20261107-0016 — 2026-11-06T21:32:11Z (قبل ~3 دقائق)
آخر 24 ساعة POS: 0 طلب (لا مستخدمين على نقاط البيع)
```

الترحيل ينتج من عامل `scripts/oracle-poll-worker.js` الذي يُشغّله
`backend/server.js:3280-3315` كل `pollMinutes` (دورتان في بعض الدقائق). هذا
العامل يقرأ من Oracle يارسوفت ويكتب قيود `yarasoft_revenue` في PostgreSQL.
**لا يمكن إيقافه دون إيقاف خدمة الـbackend نفسها** (أو تغيير `.env` وإعادة
تشغيل، وهو تغيير إنتاج إضافي).

**القرار المطلوب من المالك قبل البدء:** السماح بإيقاف خدمة الـbackend خلال
النافذة (إيقاف مؤقت، ثم تشغيل بعد الترقيات). هذا يحقق شرطَي «لا قيود» و«لا
مستخدمين» معًا، وهو الإجراء الوحيد الممكن دون لمس Oracle/YaraSoft.

إن رُفض الإيقاف: يمكن التطبيق مع استمرار الترحيل، لكن «قبل = بعد» يصبح
مستحيلًا حسابيًا على أعداد القيود والأرصدة؛ سنقارن عندئذٍ **اللقطة التاريخية
باستثناء القيود التي أُنشئت بعد T0** (`created_at >= T0`). هذا أقل صدقًا من
إيقاف الخدمة، ولن نفعله دون موافقة صريحة.

## 3) التحقق بعد التطبيق (Reconciliation)

تُقارن لقطة T0 (قبل 134 مباشرة) بلقطة T1 (بعد 143). قواعد القبول:

| البند | القبول |
|---|---|
| الحسابات الموجودة قبل (108 كودًا) | **نفس المجموع/البصمة** — لم يُحذف/يُعدَّل أي حساب قائم |
| إجمالي `chart_of_accounts` | 108 → **124** (+16 من 135 بالتصميم) |
| `journal_entries` / `journal_lines` | **قبل = بعد** حرفيًا |
| ميزان المراجعة المرحّل (posted) | مدين = دائن، وقبل = بعد |
| أرصدة 2100/1150/5000/1200/4000/3100 | قبل = بعد (نفس القيمة لكل حساب) |
| `account_mapping` | 0 أو 25 → 49، ولا صف قائم تغيّر |

استعلامات القياس (كلها PostgreSQL، `posted` فقط للميزان):

```sql
-- الحسابات القائمة قبل: احفظها كبصمة مرتبة ثم قارن
SELECT code FROM chart_of_accounts WHERE code NOT IN (…كودات 135…)
 ORDER BY code;
SELECT COUNT(*) FROM chart_of_accounts;
SELECT COUNT(*) FROM journal_entries;
SELECT COUNT(*) FROM journal_lines;
SELECT COALESCE(SUM(l.debit),0), COALESCE(SUM(l.credit),0)
  FROM journal_lines l JOIN journal_entries e ON e.id = l.entry_id
 WHERE e.status = 'posted';
SELECT l.account_code, ROUND(SUM(l.debit-l.credit),2)
  FROM journal_lines l JOIN journal_entries e ON e.id = l.entry_id
 WHERE e.status='posted'
   AND l.account_code IN ('2100','1150','5000','1200','4000','3100')
 GROUP BY l.account_code ORDER BY l.account_code;
```
