# الأرشفة خارج الموقع — دليل التشغيل

> لماذا: النسخة على القرص نفسه ليست نسخة. فشل قرص أو جهاز أو سرقة كانت
> يُفقد كل البيانات. الآن: نسخة مشفّرة على قرصين ثانويين + (اختياري) سحابة عبر rclone.

---

## 1) كيف تعمل المسار

```
database/scripts/backup.js
   └─ pg_dump → نسخة نصية محلية (database/backups/)
        └─ scripts/backup-mirror.js
             ├─ encryptBackupFile()  → تشفير GPG (‎.gpg + ‎.sha256)
             └─ mirrorFile()        → نسخ إلى D:/KarimBackups و E:/KarimBackups
                  · يرفض أي ملف ليس ‎.gpg (plaintext-mirror-refused)
                  · يتحقق من SHA-256 قبل النسخ
```

مسار النسخ الأسبوعي (`scripts/backup-offsite.bat`) ينسخ **النسخة المشفّرة فقط**
+ بصمتها، ويرفض النسخ النصي صراحةً، ثم يزامن عبر `rclone` إن كان هناك remote
اسمه `karim`.

## 2) الإعداد المطلوب (مرة واحدة)

| المتغير | القيمة | ملاحظة |
|---|---|---|
| `KARIM_BACKUP_PASSPHRASE` | عبارة مرور (≥ 12 حرفًا) | **الطريقة الموصى بها**: سرّ يحفظه المالك في مدير كلمات المرور — لا ملف ينقله، ولا مفتاح يضيع |
| `KARIM_BACKUP_GPG_RECIPIENT` | بصمة المفتاح العام (40/64 hex) | بديل لمؤسسات تفضّل إدارة مفتاح زوجي |
| `KARIM_GPG_PATH` | مسار `gpg.exe` | اختياري إن لم يكن في PATH |
| `KARIM_MIRROR_D` / `KARIM_MIRROR_E` | مجلدات المرآة | الافتراضي `D:/KarimBackups` و `E:/KarimBackups` |

**الأولوية**: عبارة المرور تُستخدم إن وُجدت، وإلا GPG. بلا أيٍّ منهما **لا تُنشأ
نسخة خارجية** (السكربت يرفض النص الصريح عمدًا — نسخة نصية على قرص ثانٍ أخطر
من بلا نسخة).

### لماذا عبارة المرور أفضل هنا

مفتاح GPG يحتاج **نقل المفتاح الخاص خارج الجهاز** — وإلا ضاعت النسخ المشفّرة
مع الجهاز. عبارة المرور لا تحتاج نقل شيء: سرّ يعرفه المالك ويصلح به أينما كانت
النسخة. لهذا هي المسار الموصى به، وGPG باقٍ كخيار.

**صيغتا الملف:**
- `.kbak` — تشفير متماثل AES-256-GCM + scrypt (عبارة المرور). الصيغة
  self-describing: تُقرأ من ترويستها.
- `.gpg` — تشفير GPG بالمفتاح العام (مفتاح المؤسسة).

## 3) إدارة الأسرار

- **عبارة المرور**: احفظها في مدير كلمات المرور (1Password / Bitwarden /
  KeePass). **فقدانها = فقدان كل النسخ المشفّرة بعبارة المرور.**
- **المفتاح الخاص لـGPG**: يجب أن يُحفظ خارج هذا الجهاز (USB آمن). المفتاح
  العام وحده هو ما يحتاجه التشفير هنا.
- **تدوير**: ولّد عبارة مرور جديدة (أو مفتاحًا جديدًا) وحدّث المتغيّر، ثم احذف
  القديم بعد نجاح نسخة جديدة.


## 4) التحقق الدوري (شهريًا)

```powershell
# 1) هل تُنشأ نسخة مشفّرة؟
node database/scripts/backup.js
# 2) هل المرآة تحتوي .gpg فقط؟
Get-ChildItem D:\KarimBackups -Recurse -File | Where-Object { $_.Extension -ne '.gpg' -and $_.Extension -ne '.sha256' }
# 3) هل تفكّ النسخة المشفّرة إلى نسخة مطابقة؟ (دورة كاملة)
gpg --output $env:TEMP\rt.sql --decrypt <latest.sql.gpg>
(Get-FileHash $env:TEMP\rt.sql).Hash -eq (Get-FileHash <original.sql>).Hash
```

## 5) الاسترجاع

```powershell
# فك التشفير بعبارة المرور (الصيغة تُكتشف تلقائيًا من ترويستها)
$env:KARIM_BACKUP_PASSPHRASE = "<عبارة المرور>"
node scripts/decrypt-backup.js <file.kbak> C:\restore\karim_erp.sql

# أو بعبارة المرور interactively (بلا echo) إن لم تكن في البيئة:
node scripts/decrypt-backup.js <file.kbak> C:\restore\karim_erp.sql

# استعادة
psql -h 127.0.0.1 -U postgres -d karim_erp_restored -v ON_ERROR_STOP=1 -f C:\restore\karim_erp.sql
```

## 6) حالة هذه البيئة (2026-10-21)

- GPG 2.5.24 مثبّت + مفتاح RSA-4096 (تشفير فقط) — خيار بديل.
- **الطريقة المعتمدة: عبارة مرور** (32 حرفًا) محفوظة في `.env` وفي
  `C:\KarimData\secrets\backup-passphrase.txt` (ACL: Administrators + SYSTEM).
  **انقلها إلى مدير كلمات المرور واحذف الملف** — هذه هي خطوة الحماية الوحيدة
  المتبقية، وهي بيدك.
- النسخ النصية القديمة على D:/E: (من قبل ضبط GPG) شُفِّرت في مكانها مع
  التحقق من دورة فك-تشفير لكل ملف (43 ملفًا، 7.3GB).
- الصيغتان موجودتان على المرايا: `.gpg` (84) و `.kbak` (2) — أداة فك التشفير
  تكتشف الصيغة تلقائيًا.
