# GATE 01 — تقييم المستودع للبرنامج السعودي

- **التاريخ:** 2026-11-10 (توقيت الجهاز UTC+3)
- **النطاق المطلوب من المالك:** تفعيل الخدمات السعودية — **مدد (Mudad/WPS)**، **الزكاة والدخل (ZATCA)** — ببنية تحتية قوية، مع **إعدادات V2**.
- **الطريقة:** جرد قراءة فقط للمستودع وقاعدة الإنتاج (استعلامات تعريفية بلا كتابة). لا كود ولا هجرة ولا تعديل إعداد في هذه البوابة.
- **تصنيف المزاعم:** `VERIFIED` (مثبت في الكود/القاعدة)، `INFERRED` (مستنتج)، `UNVERIFIED` (غير مؤكد — لا مصدر رسمي داخل المستودع)، `BLOCKED` (متعذر).

## 2) الفجوات المؤثرة

1. **أسرار الهيئة بلا خزنة:** `private_key_pem` و`csid` يُكتبان نصًا في `zatca_settings` (`zatca-settings-routes.js:361`) بلا تشفير — يجب AES-256-GCM مثل خزنة MFA.
2. **لا محرّك تكامل موحّد:** كل مزوّد جديد سيكرّر idempotency وإعادة المحاولة والتدقيق. المطلوب outbox + engine + DLQ + سجل تدقيق موحّد.
3. **لا فصل مهام (SoD):** من يضبط الإعدادات هو من يشغّل الترحيل — مطلوب صلاحيات منفصلة (إعداد/تشغيل/مراجعة).
4. **لا تقارير زكاة/دخل:** لا قواعد احتساب ولا كشوف ولا ربط بميزان المراجعة.
5. **لا مسار مدد:** WPS يتطلب ملفات/قوائم أجور وشهادات — لا شيء موجود.
6. **V2 بلا قسم امتثال:** الأقسام الحالية لا تغطي مدد/الزكاة/الدخل.

## 3) تصنيف المزوّدين (يُحدَّث بتاريخ تحقق)

| المزوّد | الوظيفة | التصنيف | ملاحظة |
|---|---|---|---|
| ZATCA FATOORA | فاتورة إلكترونية — Phase 2 | VERIFIED (كود) / UNVERIFIED (قبول) | لا شهادة قبول رسمية داخل المستودع؛ لا يجوز عرض تجربة كقبول حكومي |
| ZATCA — إقرار ضريبة القيمة المضافة | تقرير/ترحيل | VERIFIED (محلي) | الترحيل المحلي عبر خريطة الحسابات |
| ZATCA — الزكاة وضريبة الدخل | إقرارات سنوية | UNVERIFIED | لا واجهة برمجية عامة مؤكدة للإقرار؛ التصميم يبدأ بتقارير جاهزية فقط |
| Mudad (WPS) | حماية الأجور | BLOCKED | لا واجهة عامة موثّقة؛ المسار المبدئي: ملفات SIF/كشوف + استيراد إيصالات |
| GOSI / QIWA | تأمينات/عمل | UNVERIFIED | خارج طلب المالك الحالي؛ تُترك كمزوّدين في المحرّك لاحقًا |

## 4) البوابات المقترحة (01–07)

- **GATE 01 — التقييم** (هذا الملف): جرد وفجوات وتصنيف. ✅
- **GATE 02 — قرارات معمارية وschema:** ADR-001…010، جداول `integration_outbox` / `integration_events` / `integration_credentials`، صلاحيات SoD جديدة، تصميم قسم إعدادات V2. بلا تنفيذ قبل الموافقة.
- **GATE 03 — المحرّك:** outbox ذري مع الأعمال المالية، idempotency keys، إعادة محاولة أسّية، DLQ، سجل تدقيق، مراقبة.
- **GATE 04 — ZATCA:** تشديد Phase 2 فوق الموجود (UBL 2.1 كامل، PIH، CSID في الخزنة، clearance/reporting)، مع اختبارات محاكاة فقط وتصنيف واضح.
- **GATE 05 — الزكاة والدخل:** تقارير جاهزية من الأستاذ (وعاء الزكاة، صافي الدخل المعدّل)، تصدير، بلا ادعاء تقديم رسمي.
- **GATE 06 — مدد:** تصدير ملف أجور WPS + استيراد إيصالات + مطابقة؛ يبقى BLOCKED للربط المباشر حتى إثبات واجهة رسمية.
- **GATE 07 — تقوية وتحقق:** بوابات أمنية، اختبارات عزل، runbook تشغيل وتراجع، وتحديث التصنيفات بتاريخ جديد.

## 6) تصميم قسم إعدادات V2 (مسودة للنقاش)

قسم جديد «الامتثال السعودي» داخل `frontend/app/js/v2/screens/settings.js` بثلاث بطاقات:

- **ZATCA:** الحقول الحالية (قراءة/حفظ/اختبار) + تحذير «أسرار غير مشفرة» حتى GATE 04.
- **الزكاة والدخل:** السنة المالية، نسبة الزكاة، وعاء الزكاة (حساب من الأستاذ)، صافي الدخل المعدّل — عرض للقراءة أولًا.
- **مدد:** رقم المنشأة، ملف الأجور، حالة الاعتماد — قراءة/تصدير فقط (BLOCKED للربط).

الصلاحيات: `compliance.view` / `compliance.configure` / `compliance.submit` / `compliance.review` (فصل مهام)، والكتابة تتطلب تدقيقًا إجباريًا.

## 7) مخاطر وممنوعات

- لا يُدّعى قبول حكومي بلا رد رسمي محفوظ.
- لا واجهات مخترعة لمدد أو الإقرارات.
- لا تغيير في الحسابات المالية أو الأستاذ في هذه البوابات.
- أسرار الهيئة لا تخرج في أي استجابة API (تُقنَّع كما هو الحال الآن).

## 8) القرار المطلوب

الموافقة على الانتقال إلى **GATE 02** (ADRs + schema + تصميم V2 settings) بلا تنفيذ كود تشغيلي، وتأكيد تفسير «الزكاة والدخل» = **هيئة ZATCA** (فاتورة + ضريبة قيمة مضافة + تقارير زكاة/دخل) وليس جهتين منفصلتين.
