# قسم «الامتثال السعودي» في إعدادات V2 — تصميم

- **الحالة:** تصميم مقترح ضمن GATE 02 — لا تنفيذ
- **التاريخ:** 2026-11-10
- **المرجع:** ADR-009، ADR-005، ADR-001
- **الهدف:** سطح واحد يرى فيه المشغّل حالة كل مزوّد حكومي، وصحة التسليم،
  دون إظهار أي سر ودون ادعاء جاهزية غير مثبتة.

## 1. الموضع والصلاحيات

- بطاقة جديدة داخل شاشة الإعدادات القائمة
  (`frontend/app/js/v2/screens/settings.js`)، **بعد** بطاقة
  «ربط هيئة الزكاة» مباشرة، بنفس نمط `sectionCard` القائم.
- لا عنصر تنقّل جديد، ولا تغيير على `hidden_nav_pages`.
- الرؤية: `admin` أو من يملك `compliance.view`؛ غيرهم لا يرى البطاقة أصلًا
  (لا تظهر معطّلة).
- الكتابة داخل القسم بثلاث بوابات منفصلة (ADR-005):

  | الفعل | المفتاح |
  |---|---|
  | عرض الحالة والسجل والتقارير | `compliance.view` |
  | تعديل إعداد مزوّد / تدوير اعتماد | `compliance.configure` |
  | إعادة محاولة تسليم | `compliance.submit` |
  | اعتماد إعادة/استثناء (maker-checker) | `compliance.review` |

- الخادم هو الحاكم؛ إخفاء الزر تجميلي فقط. أي نداء مباشر بلا مفتاح ⇒ 403.

## 2. نموذج العرض

القسم ثلاثة أجزاء رأسية:

### أ) لافتة الحقيقة

تظهر دائمًا أعلى القسم ما دام أي مزوّد ليس `VERIFIED`:

> لا يوجد اعتماد حكومي إنتاجي موثّق لهذا المزوّد. الأرقام المعروضة حالة
> نظام، وليست قبولًا من الجهة.

مرافقة لشارة الحالة: `VERIFIED` / `INFERRED` / `UNVERIFIED` / `BLOCKED`
بألوان دلالية ونص (لا لون وحده).

### ب) بطاقات المزوّدين

| المزوّد | ما يُعرض | ما لا يُعرض |
|---|---|---|
| ZATCA | البيئة (اختبار/إنتاج)، آخر `Last Verified`، عدد الأجهزة النشطة، آخر ICV، فجوة سلسلة (نعم/لا)، انتهاء CSID، عدّاد الصادر | CSID، CSR، المفتاح الخاص |
| مدد | حالة `BLOCKED` وسببها، اكتمال بيانات الأجور محليًا (IBAN/هوية/تأمينات)، زر تصدير معطّل حتى رفع التصنيف | أي زر «إرسال» أو «اختبار اتصال» |
| التأمينات / قوى | `UNVERIFIED` + «غير مهيّأ» | أي نموذج أو نداء |

ZATCA تُدار إعداداتها التفصيلية في البطاقة القائمة؛ بطاقة الامتثال تعرض
الحالة وتشير إليها، ولا تكرر الحقول.

زر تفعيل المزوّد (`is_enabled`) معطّل ما لم يكن `VERIFIED`؛ والنداء المباشر
يرفض بـ`409 PROVIDER_NOT_VERIFIED` (ADR-001).

### ج) الصادر والسجل

- عدّادات: معلّق، قيد المعالجة، مُسلَّم، ميت (dead-letter)، أقدم صف معلّق
  (بالدقائق).
- جدول dead-letter: الوقت، المزوّد، نوع الحدث، آخر رمز خطأ، عدد المحاولات،
  إجراءان: «إعادة» (`compliance.submit`) و«اعتماد» (`compliance.review`).
- آخر 20 حدثًا داخليًا (تغيير إعداد/تدوير اعتماد) بأسماء الحقول المتغيرة فقط.
- بلا حمولات ولا أسرار ولا استجابات كاملة.

## 3. عقود API المقترحة (إضافية بالكامل)

كلها تحت `/api/integration`، `jwtAuth` + المفتاح المناسب، وحدّ معدل،
وتدقيق. لا تعديل على أي مسار قائم.

| المسار | الطريقة | المفتاح | الاستجابة |
|---|---|---|---|
| `/api/integration/health` | GET | `compliance.view` | مزوّدون + عدّادات + حالة ZATCA |
| `/api/integration/providers/:code/settings` | PUT | `compliance.configure` | تفعيل/تعطيل فقط، مع تحقق التصنيف |
| `/api/integration/credentials/:provider/:key` | PUT | `compliance.configure` | كتابة سر (write-only)، يعيد `key_name` و`rotated_at` |
| `/api/integration/outbox` | GET | `compliance.view` | صفوف بلا `payload` (بصمة ونوع وحالة فقط) |
| `/api/integration/outbox/:id/retry` | POST | `compliance.submit` | صف جديد بلاحقة `:retry:<n>` |
| `/api/integration/outbox/:id/review` | POST | `compliance.review` | `{decision, reason}` مع منع self-review |
| `/api/integration/events` | GET | `compliance.view` | أحداث منقّاة، حد أقصى 50 |

قواعد الاستجابة:

- لا حقل `ciphertext` ولا `payload` ولا `response_excerpt` كاملًا في أي قائمة.
- `Cache-Control: no-store` لكل مسارات الامتثال.
- أخطاء بصيغة المشروع: `{error, message}` برسائل عربية قصيرة.
- `request_id` في كل تدقيق.

## 4. قواعد المحتوى والوصول

- عربية أولًا، RTL، أسماء الحقول التقنية لاتينية داخل `dir="ltr"` عند اللزوم.
- جمل قصيرة مباشرة؛ بلا نصوص تعليمية أو مراجع ADR أو تواريخ تصميم في الواجهة.
- كل حقل له `<label>` مرتبط (النمط القائم يربط تلقائيًا).
- `aria-live="polite"` لرسائل النجاح/الفشل، وتركيز واضح، وأزرار بأسماء مفهومة.
- التواريخ بمنطقة آسيا/الرياض، والأرقام بفواصل عربية-لاتينية متسقة مع الشاشة.
- لا `window.alert`؛ تُستخدم `notify` القائمة.

## 5. معايير قبول قابلة للاختبار

1. admin يرى القسم؛ مستخدم بـ`compliance.view` فقط يرى قراءة بلا أزرار كتابة؛
   بلا المفتاح لا يظهر القسم.
2. لا يظهر أي من `csid`, `private_key_pem`, `csr_pem`, `ciphertext`, `payload`
   في DOM ولا في أي استجابة JSON (اختبار يفحص الحقول recursively).
3. تفعيل مزوّد غير `VERIFIED` من الواجهة معطّل، والنداء المباشر يعيد 409.
4. «إعادة» تظهر فقط بـ`compliance.submit`، و«اعتماد» فقط بـ`compliance.review`،
   ومنع self-review يعيد 409.
5. لافتة الحقيقة تظهر طالما يوجد مزوّد غير VERIFIED، وتختفي فقط عند تحقق الكل.
6. بطاقة ZATCA القائمة وسلوكها لم يتغيرا (اختبار عقد للشاشة الحالية).
7. لا تغيير في عناصر تنقّل V2.
8. أي تعديل على `frontend/app` يمر عبر بوابة إصدار الواجهة
   (`frontend:version:bump`) — يُنفَّذ في GATE 03 لا هنا.
