# التقرير اليومي بالبريد — نظام حورس

أضيفت إلى النسخة الأحدث من نظام حورس خدمة تقرير يومي تعتمد على قاعدة البيانات مباشرة. التقرير يتضمن إجمالي المبيعات وعدد الفواتير والخصومات والضريبة، الإيراد حسب القسم، طرق الدفع، الأصناف الأكثر مبيعًا، المصروفات، الحضور والانصراف، والأصناف التي وصلت إلى الحد الأدنى للمخزون.

## المعاينة والإرسال اليدوي

بعد تسجيل دخول مدير أو مسؤول مخول، يمكن معاينة تقرير يوم محدد من خلال:

```text
GET /api/reports/daily?date=YYYY-MM-DD
```

ويمكن إرسال التقرير يدويًا من خلال:

```text
POST /api/reports/daily/send
Body: { "date": "YYYY-MM-DD" }
```

يُسمح بالمعاينة للأدوار `admin` و`manager` و`auditor`، بينما الإرسال اليدوي متاح للأدوار `admin` و`manager` فقط.

## الإرسال التلقائي

يعمل خادم حورس على فحص وقت التقرير كل ثلاثين ثانية، ويرسل التقرير مرة واحدة يوميًا عند تطابق الوقت المحدد. الإعداد الافتراضي هو الساعة 23:00 بتوقيت الرياض، ولا يبدأ الإرسال إذا كانت إعدادات SMTP ناقصة.

أضف القيم التالية إلى ملف `.env` على جهاز الخادم فقط، ولا تضع كلمة المرور في المستودع أو ملفات التوزيع:

```env
REPORT_TIMEZONE=Asia/Riyadh
REPORT_EMAIL_TIME=23:00
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=reports@example.com
SMTP_PASS=APP_PASSWORD_OR_SMTP_SECRET
REPORT_EMAIL_FROM=reports@example.com
REPORT_EMAIL_TO=owner@example.com,manager@example.com
REPORT_EMAIL_SUBJECT=تقرير حورس اليومي
```

استخدم **كلمة مرور تطبيق** أو بيانات SMTP مخصصة للتقارير، وليس كلمة مرور الحساب الشخصية. بعد تعديل `.env` أعد تشغيل خدمة حورس، ثم راقب السجل بحثًا عن رسالة `daily-report`.

## السلوك الآمن

إذا لم تُضبط إعدادات SMTP، يظل النظام يعمل بصورة طبيعية ويظهر تحذير واضح في السجل، ولا يحاول إرسال رسائل أو طباعة أسرار. كما أن مسارات التقرير محمية بالمصادقة والصلاحيات، ويُهرب محتوى HTML قبل عرضه داخل التقرير.

## التحقق

```bash
npm test
npm audit --omit=dev --audit-level=moderate
```

الاختبار الحالي يتضمن اختبارات تنسيق التقرير وحماية HTML وحالة إعداد SMTP، وقد نجحت اختبارات الوحدة بعد الإضافة.
