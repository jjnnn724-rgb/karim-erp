`npm test` تلقائيًا. القواعد الصفرية (eval / new Function) لا تُستثنى إطلاقًا.

## بطاقة متابعة SEC-ZKTECO-531 (Ticket)

| الحقل | القيمة |
|---|---|
| Ticket | **SEC-ZKTECO-531** (مسجّل في `scripts/security-baseline.json` → `_exceptions`) |
| الموقع | `frontend/app/js/v2/screens/zkteco.js:531` — `rowsHost.innerHTML = ... ${rows} ...` |
| القاعدة | `html-unescaped` — 10 إصابات مقابل حصّة 9 (الحادية عشرة هي `${rows}`) |
| المالك | جلسة واجهة الحضور (شاشة البصمة) |
| **Deadline** | **2026-12-06** — بعدها يعود الانتهاك ويفشل `npm test` تلقائيًا؛ لا تجديد صامت |
| حالة الإصابة | `${rows}` سلسلة بُنيت مسبقًا بحقول مهرّبة عبر `esc()` — ليست حقنًا خامًا، لكن البوابة لا تستطيع إثبات ذلك |

**معايير الإغلاق (Acceptance):**

1. إعادة بناء صفوف الجدول بعُقد DOM (أو تمرير `rows` عبر دالة تبني HTML آمنًا
   بمكافئ `esc()` على المتغير كاملًا)، بحيث يصبح `${rows}` غير موجود.
2. إصابة `html-unescaped` في `frontend/app/js/v2/screens/zkteco.js` تعود
   ≤ 9 (أو 0 بحسب السياق).
3. حذف صف الاستثناء من `scripts/security-baseline.json` الأسبوع الماضي.

**التحقق:**

```bash
node scripts/security-gate.js
```

**إن لم يُغلق قبل 2026-12-06:** تبقى القاعدة حمراء في CI ولا تُدمج أي تغييرات
جديدة على الملف حتى يعود العدد تحت الحصّة — هذا هو الغرض من تاريخ الانتهاء.

## لماذا استثناء وليس إصلاحًا فوريًا

`zkteco.js` ملف جلسة أخرى نشطة (شاشة ربط البصمة). تعديله من هذه الجلسة
يخالف قاعدة «لا تلمس عمل جلسة أخرى». الاستثناء يوثّق الدين بدل إخفائه،
وله تاريخ انتهاء لا يمكن تجديده بصمت.
