# دليل التشغيل والنشر (Deployment Guide)

يوضح هذا الدليل خطوات تشغيل خادم نظام "karim ERP LAN Edition" من الصفر، ليصبح النظام جاهزاً لاستقبال اتصالات من الأجهزة الأخرى في الشبكة.

## المتطلبات المسبقة
1. **Node.js**: تأكد من تثبيت Node.js 20 أو أحدث على جهاز الخادم. (لا يشترط وجوده في الأجهزة العميلة؛ نسخة Electron المعبأة تحتوي runtime الخاص بها).
2. **PostgreSQL**: لا يتطلب التثبيت! يتم تحميل نسخة محمولة (Portable) تلقائياً عند التشغيل الأول.

## خطوات التشغيل الأولية

### 1. إعداد المشروع
1. انسخ مجلد `karim-erp-system` إلى جهاز الخادم الخاص بك.
2. ضع ملفك الأصلي `4Global_View_Premium_v10-4.html` داخل المجلد الرئيسي (نفس مسار `package.json`).
3. قم بفتح نافذة سطر الأوامر (CMD أو PowerShell) في هذا المجلد.
4. قم بتثبيت الحزم المطلوبة:
   ```bash
   npm install
   ```

### 2. تحميل قاعدة البيانات المحمولة
قم بتشغيل سكربت التحميل ليقوم بتحميل واستخراج PostgreSQL المحمول تلقائياً:
```bash
node database/scripts/download-pg.js
```
*ملاحظة: حجم التحميل تقريباً 300 ميجابايت، قد يستغرق بعض الوقت بناءً على سرعة الإنترنت.*

### 3. تطبيق التعديلات على واجهة المستخدم (HTML Patching)
لن يتم التعديل يدوياً، يوجد سكربت جاهز يقوم بتطبيق التعديلات المطلوبة (API_BASE ودوال حفظ/تحميل البيانات) ونسخ الملف النهائي إلى `frontend/app`.
```bash
node scripts/patch-html.js
```

### 4. التشغيل الموحد
الآن النظام جاهز للتشغيل. يمكنك بدء الخادم وقاعدة البيانات بنقرة واحدة:
```bash
node scripts/start.js
```

هذا السكربت سيقوم بـ:
1. عرض عناوين IP المتاحة للاتصال (سيتم إبراز العنوان المخصص للشبكة المحلية).
2. تشغيل خادم PostgreSQL (وتشغيل مجلد الـ Data وملفات الـ Migrations إذا كانت هذه المرة الأولى).
3. تشغيل الـ Backend API على المنفذ `5000`.
4. محاولة فتح المتصفح تلقائياً على جهاز الخادم.

## اتصال الأجهزة العميلة (Client Access)
- **لا حاجة لتثبيت أي برنامج على الأجهزة العميلة.**
- فقط قم بفتح متصفح الويب (Chrome, Edge, Safari) في الهاتف أو الكمبيوتر الآخر في نفس الشبكة، وأدخل الرابط الذي ظهر في الشاشة السوداء للخادم.
- **مثال للرابط:**
  `http://192.168.1.15:5000/app/index.html`

## استكشاف الأخطاء الشائعة وحلولها
1. **لم يتمكن جهاز العميل من الاتصال:**
   - **السبب:** جدار الحماية (Firewall) في جهاز الخادم يمنع الاتصال.
   - **الحل:** اذهب إلى "Windows Defender Firewall" -> "Advanced Settings" -> "Inbound Rules" وقم بإضافة قاعدة جديدة للسماح بالمنفذ (Port) رقم `5000`.
   - راجع [دليل الشبكة NETWORK.md](./NETWORK.md) للحصول على التفاصيل.

2. **خطأ "PostgreSQL binaries not found":**
   - **السبب:** لم يتم تحميل PostgreSQL أو تم حذفه من المسار.
   - **الحل:** أعد تشغيل السكربت `node database/scripts/download-pg.js` وتأكد من وجود مجلد `bin` داخل `database/bin`.

3. **البيانات لا تظهر أو لم تُحفظ بنجاح:**
   - تحقق من ظهور رسالة "تم الحفظ محلياً فقط" في النظام؛ إذا ظهرت فهذا يعني أن هناك انقطاعاً في الاتصال بالخادم.
   - راجع شاشة الكونسول في الخادم لمشاهدة أي أخطاء.

## Code Signing — القرار والخطة الزمنية (B.7)

**القرار الحالي (2026-07-17):** لا توجد شهادة توقيع كود (Code Signing Certificate) متاحة للمشروع حالياً. النظام يُبنى بدون توقيع رقمي (`signAndEditExecutable: false` في `package.json`).

**التأثير:**
- مستخدمو Windows سيرون تحذير SmartScreen عند أول تشغيل لـ `Karim-ERP-Setup-2.1.0.exe`
- يتطلب من المستخدم النقر على "More info" ثم "Run anyway" لتجاوز التحذير

**الخطة الزمنية:**
- **Q3 2026**: التواصل مع DigiCert / Sectigo لشراء EV Code Signing Certificate (~$400/سنة)
- **Q4 2026**: دمج الشهادة في pipeline البناء + تفعيل `signAndEditExecutable: true`
- **بعد التفعيل**: تحديث كل التحذيرات في README.md و docs/ لإزالة إشارة SmartScreen

**البدائل المؤقتة:**
1. توقيع ذاتي (self-signed) — لا يحل تحذير SmartScreen لكنه يثبت أن الملف لم يُعدّل
2. نشر النسخة على GitHub Releases + طلب من المستخدمين التحقق من SHA256
3. تعليمات للمستخدم بتجاوز SmartScreen (موجودة في README-WINDOWS.md)

## PostgreSQL Portable — خطة التحديث الأمني (C.11)

**النسخة الحالية المُضمَّنة:** PostgreSQL 16.x (Windows x64 Portable)
**آخر تحديث أمني مُطبَّق:** 2026-07-15 (مراجعة CVEs)
**المصدر:** https://www.enterprisedb.com/download-postgresql-binaries

**آلية التحديث الدورية:**
1. **شهرياً**: مراجعة https://www.postgresql.org/support/security/ للـ CVEs الجديدة
2. **كل 3 أشهر**: تحميل نسخة PostgreSQL Portable جديدة من EnterpriseDB
3. **عند التحديث**:
   - نسخ احتياطي كامل لـ `database/data/` قبل أي تغيير
   - استبدال `database/bin/` بالنسخة الجديدة
   - اختبار التشغيل على بيئة staging
   - تشغيل `pg_upgrade` إذا لزم الأمر (للنسخ الكبرى فقط)
   - تحديث هذا القسم بتاريخ التحديث الجديد

**الإصدارات المدعومة رسمياً (2026-07):** PostgreSQL 13, 14, 15, 16, 17
**الإصدار الموصى به للإنتاج:** PostgreSQL 17 (أحدث — لكنه غير مُضمَّن حالياً)

**الترحيل إلى PostgreSQL نظامي:**
لو فضّلت عدم استخدام النسخة المحمولة، يمكنك:
1. تثبيت PostgreSQL على مستوى النظام (`winget install PostgreSQL.PostgreSQL.16`)
2. ضبط `DB_HOST=localhost`, `DB_PORT=5432`, `DB_PASSWORD=<your-strong-password>` في `.env`
3. حذف `database/bin/` لتوفير المساحة
4. النظام سيعمل بنفس الطريقة — `start-pg.js` يكتشف الـ PostgreSQL الخارجي تلقائياً

## ZATCA Phase-2 — الحالة الفعلية (C.13)

**الحالة:** بنية تحتية جاهزة، **غير مفعّلة بعد**.

تم بناء كل المكونات التقنية لـ ZATCA Phase-2 (QR TLV، توقيع ECDSA، سلسلة hash، طابور async) لكن **لم يتم الاتصال الفعلي** بخوادم ZATCA (Sandbox أو Production).

**المهام الناقصة قبل التفعيل:**
1. توليد CSR (Certificate Signing Request) من ZATCA portal
2. طلب Compliance CSID من بيئة Sandbox
3. إكمال `buildZatcaUblXml()` في `backend/cashier-module/zatca-queue.js`
4. توقيع XML بالشهادة
5. الإرسال الفعلي عبر mTLS إلى `https://gw-fatoora.zatca.gov.sa/api/v1/invoices/...`
6. معالجة الاستجابة + تحديث `pos_zatca_invoice_queue.status`
7. اختبار end-to-end كامل

**التوثيق الكامل:** راجع `docs/CASHIER-MODULE.md` قسم "ZATCA — المهام الناقصة".
