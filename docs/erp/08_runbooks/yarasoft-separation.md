# Runbook: فصل تكامل Yarasoft/Oracle بأمان
**قرار المالك (2026-10-03):** التكامل إضافة اختيارية قد تُفصل في أي وقت — النظام يجب ألا يعتمد عليه جوهريًا.
**آخر أرشيف كامل:** `C:\HorusData\yarasoft-archive\karim_erp-yarasoft-mirror-20261003.dump` (65 جدولًا، 62MB، تحقق pg_restore -l ✓)

## 1. ماذا يتبع Yarasoft وماذا لا
| يعتمد عليه | لا يعتمد عليه |
|---|---|
| جدول `revenues` (22K+ صف مستورد — يتوقف نموه عند الفصل) | وحدة كاشير كاريم POS (مستقلة تمامًا) |
| صفحات واتساب/تقارير مرآة الفواتير | الدفتر المحاسبي GL (المبيعات المستوردة لا تُرحَّل أصلًا — قرار R3) |
| مطابقة المنتجات yarasoft_product_mapping | المخزون والمستودع (حركات داخلية) |
| عامل oracle-poll-worker | الحضور/الرواتب/المستخدمين |

## 2. الفصل المؤقت (إيقاف تشغيلي — قابل للرجوع)
```bat
:: في .env غيّر ثم أعد تشغيل الخادم:
YARASOFT_ENABLED=false
YARASOFT_ORACLE_ENABLED=false
YARASOFT_ORACLE_LIVE=false
```
**مثبت تجريبيًا:** خادم أُقيل بهذه الرايات أقلع طبيعيًا 100% (اختبار Stage 3 على 5001/5002 — boot نظيف).
الأثر: يتوقف الاستيراد والمزامنة فقط؛ كل بيانات التاريخ تبقى قابلة للقراءة والتقارير.

## 3. الفصل النهائي (خطوات مرتبة — لا تنفذ إلا بأمر صريح)
1. أرشيف محدث: أعيد تشغيل سكربت الأرشفة (موجود في `%TEMP%\run-archive.cmd` — أعده بنمط هذا الملف §1) بعد آخر مزامنة.
2. أوقف العامل: `taskkill` على `oracle-poll-worker.js` أو أزل مهمته المجدولة.
3. عدّل الرايات (§2) وأعد التشغيل.
4. **لا تحذف جداول `ora_*`/`ys_*`/`yarasoft_*` من القاعدة** — الأرشيف يكفي للفصل؛ الحذف قرار مستقبلي منفصل بعد 3 أشهر تشغيل بلا تكامل (بيانات تاريخية للمراجعة).

## 4. ما يحدث لسير المبيعات بعد الفصل
- مبيعات جديدة تُسجل عبر **كاشير كاريم** (pos_orders → revenues → GL مع COGS بعد إصلاح C1).
- أرقام الإيرادات التاريخية من يارسوفت تبقى في `revenues` (source يذكر اسم الكاشير) وتظهر في P&L بفصلها عن POS.
- يُنصح عند الفصل: تفعيل نقاط بيع كاريم فعليًا في الأقسام كي لا يتوقف سجل الإيرادات.

## 5. الرجوع عن الفصل
أعد الرايات true + أعد تشغيل الخادم + شغّل عامل Oracle. البيانات تستمر من آخر checkpoint (device_sync_state / invoice_import_log).
