## العقيدة
1. **الرفض عند الباب، لا الإصلاح بعد الاختراق:** كل تغيير يُفحص قبل الالتزام، قبل الدفع، وقبل الدمج. فشل واحد = رفض كامل.
2. **ratchet لا يُرفع:** حدود الأمان/lint/الألوان/ميزانية الحزم تُشدّ ولا تُرخي لتخضير فشل. أصلح السبب، لا الحد.
3. **التاريخ مصون:** الترحيلات المطبقة لا تُعدّل ولا تُحذف (بصمات sha256 حاجبة)؛ الإصلاح بترحيل جديد مسجل بوعي.
4. **الإنتاج مقدس:** لا كتابة على karim_erp، لا إعادة تشغيل لخوادمه، لا مساس بملفات يخدمها. الاختبار على المعزول (karim_erp_test / :5299) فقط.
5. **الدليل لا الادعاء:** كل «تم» خلفه تشغيل فعلي؛ كل بوابة لها اختبار يثبت أنها ترفض العبث.

## الأبواب (بالترتيب الذي يمر به الكود)
### الباب 1 — pre-commit (محلي، ثوانٍ)
`scripts/git-hooks/pre-commit`: أسرار المتتبع + عدم المساس بالترحيلات + اتساق إصدار الواجهة.
**مُختبر:** سر مزروع ⇒ الالتزام رُفض فعليًا (HEAD لم يتغير).

### الباب 2 — pre-push (محلي، ~دقيقتان)
`scripts/git-hooks/pre-push` → `npm run fortress` (القياسي):
8 بوابات سريعة (أسرار/ترحيلات/إصدار/ألوان/Docker/handlers/CSP/dispatch) + 4 متوسطة (ESLint حصص/أنواع/أمان XSS/حقن/اختبارات نقية).
التثبيت لكل worktree: `npm run hooks:install`.

### الباب 3 — CI على العدّاد (push + كل PR)
- **V3 CI:** أربع مراحل مسماة (typecheck → vitest → build → biome check) + e2e العام + ميزانية gzip. فشل تنزيل Chromium محصّن بـ3 محاولات + تراجع + سجل مرفوع.
- **CI Probe (Probe):** فحص سريع مستقل.
- **CI/CD Pipeline (القديم):** **أخضر بالكامل منذ 2026-11-20** (أمن npm → Lint/TypeCheck → Unit Tests بعتبات التغطية → Smoke → E2E Playwright). جذر الفشل التاريخي (npm ci EUSAGE — قفل ناقص تبعيات electron-builder بين npm 10/11) أُصلح، ثم دين الأنواع سُدّد، ثم فجوات بيئة العدّاد (.env اختياري، pg_restore عابر للمنصات، postgres:18 مطابقة للإنتاج، منح ما بعد 113 بترحيل 154). Integration/Build مقصورة على main بتصميمها.

### الباب 4 — حماية main على GitHub (مُطبقة ومُتحقق منها بالقراءة)
- **PR إلزامي + مراجعة مالك الكود (CODEOWNERS) + إغلاق المحادثات**
- **فحوص مطلوبة (7):** `🧱 V3 Gate (pnpm — typecheck/test/build/lint + e2e)` + `Probe` + `🔒 Security Audit (npm)` + `🧹 Lint, Format & TypeCheck` + `🧪 Unit Tests` + `🔥 Smoke Test (Startup + Health)` + `🎭 E2E (Playwright)` — كلها تعمل على **كل PR** (فحص غائب = دمج معلّق، لا ممر صامت)
- **strict:** يجب أن يكون الفرع محدثًا بـmain قبل الدمج
- **ممنوع:** force-push، حذف الفرع، التجاوز حتى للـadmins (`enforce_admins`)

### الباب 5 — حواجز التشغيل (داخل النظام نفسه)
حارس قاعدة الإنتاج (fail-closed) · تدقيق append-only (003 §5.4) · قفل دخول دائم (153) · step-up MFA للاستعادة · CSP مثبّتة · rate-limit يتدهور مغلقًا · بث Socket.io مصادَق افتراضيًا · حراس COA (نوع/قفل/ترخيص) · ميزانية حزمة حاجبة.


## الطوارئ الموثقة (ليس بابًا خلفيًا معتادًا)
`git commit --no-verify` يتجاوز الباب المحلي فقط — **CI وحماية main ما زالا يحكمان الدمج**. أي تجاوز يُذكر في رسالة الالتزام ويُراجع في PR. لا يوجد تجاوز لحماية main إلا بتعديل الإعداد نفسه (قرار مالك موثق).
