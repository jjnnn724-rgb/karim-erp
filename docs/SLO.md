## التشغيل والمراقبة
```bash
# فحص لحظي (اعتمادات من البيئة فقط — لا تُطبع):
SLO_BASE_URL=http://127.0.0.1:5000 SLO_USER=... SLO_PASS=... SLO_API_KEY=... \
  node scripts/slo-check.js
# exit 0 = سليم · 1 = خرق SLO · 2 = تعذر القياس
```
- يُوصى بجدولة الفحص كل 5 دقائق (مراقبة خارجية/cron) وتصعيد أي exit 1.
- خرقان متتاليان = تصعيد فوري للمالك؛ خرق الإتاحة = فتح تحقيق في السبب الجذري قبل أي نشر.
- `/api/health` و`/ready` يفحصان المكونات الحرجة (database/outbox/websocket) — أي fail فيها حاجب للتشغيل.

## قواعد الاشتقاق
- الحدود ratchet: تُشدّ مع تحسن القياسات، ولا تُرخي لتخضير فشل.
- أي نشر جديد يمر بالقلعة (`npm run fortress`) — راجع `docs/FORTRESS.md`.
- قياس ما قبل النشر وما بعده بنفس الأداة؛ الفرق >20% في p95 = انحدار يستوجب التحقيق.
