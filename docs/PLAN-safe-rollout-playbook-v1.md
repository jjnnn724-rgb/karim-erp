# خطة التنفيذ الآمنة (Playbook) — HR-PWA v1.0

**الوثيقة الأم للمتطلبات:** `docs/SPEC-employee-pwa-attendance-geofence-v1.md`
**الغرض:** تحويل المواصفات إلى خطوات تنفيذ مرقّمة، كل خطوة منها **قابلة للنشر بمفردها، قابلة للتراجع خلال دقائق، ولا تكسر السيرفر العامل في أي لحظة**.
**الحالة:** بانتظار اعتماد المالك لبدء S0
**التاريخ:** 2026-09-28

---

## 1. عقد السلامة (Safety Contract) — قواعد لا تُخترق

هذه القواعد ملزمة لكل خطوة في هذه الخطة. مخالفة أي منها = إيقاف التنفيذ فورًا:

| # | القاعدة |
|---|---|
| G1 | **خطوة واحدة لكل نشر.** لا يُنشر تعديلان مستقلان في نفس اللمسة — كل خطوة Commit مستقل برسالة معيارية `step(Sx): ...` |
| G2 | **لا نشر بدون نقطة استرجاع.** قبل كل خطوة: نسخة قاعدة بيانات بعمر أقل من 24 ساعة + Commit ثابت على Git |
| G3 | **الهجرات إضافية فقط.** جداول وأعمدة جديدة بقيم افتراضية — ممنوع تعديل أو حذف أي Migration قديمة أو عمود قائم. التراجع عن DB لا يُحتاج أبدًا لأن كل ما نضيفه يبقى صامتًا |
| G4 | **كل ميزة جديدة تولد مغلقة.** مسار البصمة يعمل بالكود لكنه يرد `PUNCH_PORTAL_DISABLED` حتى يفتحه المالك من الإعدادات — التفعيل قرار إداري بنقرة، لا بنشر |
| G5 | **مفتاح قتل فوري (Kill-Switch).** إيقاف أي ميزة حية يتم من شاشة الإعدادات أو تعديل سطر واحد في `.env` — بدون إعادة نشر كود، وأقصى تأخير إعادة تشغيل = 30 ثانية |
| G6 | **نشر في نافذة آمنة** فقط: بعد إغلاق آخر وردية وبعد نجاح النسخة الاحتياطية اليومية |
| G7 | **بوابة تحقق إلزامية.** كل خطوة لها قائمة أوامر تحقق محددة النتيجة (أسفل) — أي بند أحمر = التراجع فورًا ثم التحليل، لا "نكمل ونشوف" |
| G8 | **السيرفر الحي لا يُجرَّب عليه.** التجريب على نسخة محلية/جهاز التطوير؛ السيرفر الحي يستقبل فقط كودًا مرّ ببوابة G7 كاملة |

## 2. بروتوكول النشر الموحد (يُنفَّذ مع كل خطوة S1 → S8)

```
1. نسخة احتياطية:     node database/scripts/backup.js   → نجاح + التحقق من ملف اليوم
2. تثبيت الكود:        Commit مستقل للخطوة على Git
3. إعادة التشغيل:      node scripts/stop.js && node scripts/serve.js   (≈ 30 ثانية انقطاع)
4. بوابة التحقق:       GATE السطرية للخطوة (كلها خضراء) 
5. مراقبة:            15 دقيقة صحة + CPU + سجل الأخطاء قبل إعلان نجاح الخطوة
```

### بوابة التحقق المعيارية (GATE) — تُنفَّذ حرفيًا بعد كل خطوة

| الفحص | الأمر | النتيجة المطلوبة |
|---|---|---|
| سلامة الكود | `node --check <الملفات المعدلة>` | بلا أخطاء |
| جودة الكود | `npx eslint .` | **0 errors** (التحذيرات الأسلوبية مقبولة) |
| الاختبارات | `node scripts/test.js all` | **نجاح: 4 / فشل: 0** |
| صحة الخادم | `curl -sk https://127.0.0.1:5000/api/health` | `status: ok` + كل المكونات ok |
| الاستهلاك | قياس CPU لمدة 20 ثانية (الأداة الجاهزة) | < 10% نواة (الوضع الطبيعي ≈ 1.5/20 ثانية) |
| الواجهة | فتح الشاشات الحرجة من متصفح | لا انحدار (المكتب + الجوال) |

## 3. بروتوكول الطوارئ (لو حصل كسر رغم كل شيء)

```
T+0   إيقاف فوري:            node scripts/stop.js
T+1   إطفاء الميزة الجديدة:   تعطيل العلم في .env أو الإعدادات
T+2   الرجوع لنقطة سليمة:     git checkout <tag آخر خطوة خضراء>  (البنية DB لا تُمس)
T+3   تشغيل:                 node scripts/serve.js → بوابة التحقق المعيارية
T+4   قاعدة البيانات (فقط لو الهجرة نفسها هي المشتبه — لن يحدث بحكم G3):
      node database/scripts/restore.js  ← من نسخة قبل الخطوة
T+5   توثيق الحادثة في سجل الخطوات قبل أي محاولة إعادة
```

أقصى زمن استرجاع متوقع: **أقل من 5 دقائق** (بدون لمس قاعدة البيانات أساسًا).

## 4. أعلام الميزات (Feature Flags) — لوحة التحكم المركزية

| العلم | القيمة الافتراضية عند النشر | أين يُضبط | التأثير عند الإطفاء |
|---|---|---|---|
| `PUNCH_PORTAL_ENABLED` | `false` | إعدادات النظام (مباشر) | زر البصمة يختفي + المسار يرد `PUNCH_PORTAL_DISABLED` |
| `PUNCH_GEOFENCE_ENABLED` | `false` | إعدادات النظام (مباشر) | طبقة L2/L3 تُتخطى (تبقى L1 الشبكة إلزامية دومًا) |
| `PUNCH_DEVICE_BINDING` | `true` | إعدادات النظام (مباشر) | ربط الجهاز L4 |
| `PUNCH_SELFIE_ENABLED` | `false` | إعدادات النظام (مباشر) | لقطة التحقق L5 |
| `PUNCH_RADIUS_METERS` | `120` | إعدادات النظام (مباشر) | نصف قطر النطاق |
| `MOBILE_UI_V2` | `true` للموظف فقط | `.env` | واجهة الجوال الجديدة للتجربة قبل التعميم |

قاعدة: **المسارات الجديدة تُضاف للسيرفر من اللحظة الأولى لكنها مغلقة بالعلم** — هذا يجعل كل نشر "إضافة صامتة" حتى يقرر المالك فتحها.

## 5. خطوات التنفيذ (S0 → S10)

### المرحلة صفر — نقطة الاسترجاع (لا تمس السيرفر إطلاقًا)

#### S0.1 تثبيت الوضع الحالي على Git
- **التغيير:** Commit واحد لكل الإصلاحات الحالية (258 ملفًا: إصلاحات ESLint، lan-discovery، dotenv/logger، الاختبارات) + Tag اسمه `v4.7-stable-fixed`
- **آلية عدم الكسر:** لا نشر ولا تشغيل — توثيق فقط
- **بوابة التحقق:** `git log` يُظهر الـ Commit + `git tag` يُظهر النقطة
- **التراجع:** لا يلزم (لا تغيير تشغيلي)

#### S0.2 نسخة احتياطية معتمدة
- **التغيير:** لا شيء — تشغيل `node database/scripts/backup.js` والتأكد من نجاح ملف اليوم
- **بوابة التحقق:** وجود ملف النسخة + ملف `.sha256` الخاص بها

> بعد S0.1 + S0.2 أصبحنا نتحرك داخل شبكة أمان كاملة: أي لحظة نستطيع العودة لكود وبيانات معروفتين سليمتين.

---

### المرحلة الأولى — طبقة السيرفر (الإضافة الصامتة)

#### S1 الهجرات الإضافية (Migration 075)
- **التغيير:** ملف جديد `database/migrations/075_punch_portal.sql` يُنشئ:
  - جدول `punch_devices` (ربط جهاز الموظف — L4)
  - جدول `punch_attempts` (سجل كل محاولة: موظف/وقت/IP/مسافة/دقة/سبب/نتيجة)
  - صفوف الإعدادات الافتراضية للأعلام أعلاه
- **آلية عدم الكسر:** إضافة صافية — لا لمس لأي جدول قائم؛ التطبيق عبر `node database/scripts/run-migration.js database/migrations/075_punch_portal.sql`
- **بوابة التحقق:** الاستعلام `SELECT ... FROM punch_attempts LIMIT 1` يعمل + GATE المعيارية
- **التراجع:** غير مطلوب (الجداول الفارغة صامتة تمامًا)

#### S2 مسار البصمة على السيرفر — مولود مغلقاً
- **التغيير:** ملف جديد `backend/attendance-portal-routes.js` + توصيله في `server.js` (أسطر معدودة):
  - `POST /api/attendance/punch` بفحوص L1→L5 بالتسلسل المحدد في الوثيقة الأم §5.3
  - عند نجاح كل الفحوص: استدعاء `processPunch({source:'portal'})` — نفس محرك الحضور الذكي القائم
  - العلم `PUNCH_PORTAL_ENABLED=false` → كل الطلبات ترد `PUNCH_PORTAL_DISABLED` (المسار موجود، ميزة ميتة حتى التفعيل)
- **آلية عدم الكسر:** كود جديد في ملف جديد + نقطة توصيل واحدة؛ صفر تعديل في مسارات قائمة؛ محرك الحضور يُستدعى لا يُعدَّل
- **بوابة التحقق:** GATE المعيارية + اختبار يدوي: نداء المسار يرد `PUNCH_PORTAL_DISABLED` (إثبات أن القفل يعمل)
- **التراجع:** تعطيل التوصيل في `server.js` (سطر واحد) أو الرجوع للـ Commit — الجداول تبقى (صامتة)

#### S3 حصيلة اختبارات سيناريوهات الرفض/القبول
- **التغيير:** ملف جديد `tests/punch-portal.test.js` — 12 سيناريو من الوثيقة الأم §5.7 (خارج الشبكة، داخل النطاق، GPS مزيف، دقة ضعيفة، جهاز غير مربوط، تكرار 5 دقائق، إلخ)
- **آلية عدم الكسر:** اختبارات فقط
- **بوابة التحقق:** `npx jest tests/punch-portal.test.js` → 12/12 + GATE المعيارية (الإجمالي يصبح 893 اختبارًا)
- **التراجع:** لا يلزم

> **نقطة تفتيش إدارية:** نهاية المرحلة الأولى = السيرفر الحي شغّال بنفس سلوكه القائم 100%، والبصمة الجديدة موجودة كاملة لكنها مغلقة. لا شيء تغيّر للمستخدم النهائي. هنا يُراجع المالك الحالة قبل فتح واجهة الجوال.

### المرحلة الثانية — واجهة الجوال (تظهر للموظف بعد قرار المالك)

#### S4 هيكل الجوال: شريط التنقل السفلي + شاشة الموظف الرئيسية
- **التغيير:** CSS إضافي (طبقة mobile-first جديدة — لا تعديل أنماط قائمة) + وحدة `features/mobile-shell.js` + تعديل `page-router` بنمط موحّد
- **آلية عدم الكسر:** الشاشات القائمة كلها محفوظة؛ الجديد يظهر **لدور الموظف فقط** (admin/manager يكملون على الواجهة الحالية) حتى S7
- **بوابة التحقق:** GATE المعيارية + فحص العرض على 360×640 و390×844 + اختبار انحدار الشاشات الإدارية على المكتب

#### S5 زر البصمة في شاشة الموظف
- **التغيير:** بطاقة البصمة (حالة الآن + زر كبير + رسائل الرفض المفهومة بالعربي لكل كود: "أنت خارج نطاق المطعم"، "لا يمكن البصمة من خارج شبكة المطعم"…) + جمع الموقع لحظة الضغط فقط
- **آلية عدم الكسر:** الزر يظهر فقط عندما `PUNCH_PORTAL_ENABLED=true` — أي أنه لا يظهر إطلاقًا حتى مرحلة S9
- **بوابة التحقق:** GATE + تجربة الرفض الحقيقي من خارج الشبكة (على جهاز تطوير) ورسالة الرفض تظهر سليمة

- **التغيير:** تحويل عرض الجداول للبطاقات على الشاشات الصغيرة + حالات الشبكة الواضحة (تم/فشل/أعد المحاولة) للبصمة والعمليات الحرجة
- **بوابة التحقق:** NFR-M2 من الوثيقة الأم (3 مقاسات × متصفحان × RTL)
- **التراجع:** طبقة CSS معزولة — إزالتها سطر واحد

> **نقطة تفتيش إدارية:** واجهة الجوال مكتملة، والبصمة ظاهرة لكنها لا تزال مغلقة بالمفتاح المركزي.

## 7. لماذا هذه الخطة لا تكسر السيرفر؟ (خلاصة الضمانات)

1. **كل نشر هو إضافة صامتة**: جداول فارغة، مسار مغلق، علم مطفأ — السيرفر يتصرف كما لو أن الكود غير موجود.
2. **التفعيل منفصل عن النشر**: فتح الميزة بنقرة من الإعدادات في اليوم الذي يختاره المالك، وبإمكانه إغلاقها بنفس النقرة.
3. **قاعدة البيانات محصنة هيكليًا**: لا migration واحدة تمس جدولاً قائماً — فلا يوجد سيناريو "الهجرة كسرت البيانات".
4. **كل خطوة لها زر رجوع**: Commit مستقل + Tag + نسخة احتياطية = استرجاع أقل من 5 دقائق بأي لحظة.
5. **بوابة تحقق آلية معيارية** بعد كل خطوة بنفس الأدوات التي أثبتت صحتها في فحص النظام الشامل (881 اختبارًا + صفر أخطاء lint + فحص الصحة + قياس CPU).
