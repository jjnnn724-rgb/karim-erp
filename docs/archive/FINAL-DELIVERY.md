# مطاعم الشرفة العالمية — karim ERP v3.1.0 — حزمة التسليم الإنتاجية

## حالة الإصدار

هذه نسخة التسليم الإنتاجية لنظام **مطاعم الشرفة العالمية**. يعتمد النظام على Node.js وExpress وPostgreSQL 16 وSocket.IO، وتُعد PostgreSQL مصدر الحقيقة الوحيد للبيانات التشغيلية. لا تعتمد الواجهة على بيانات أصناف أو أقسام أو مستخدمين ثابتة؛ كل القراءة والحفظ والتحديث يتم عبر API ومعاملات PostgreSQL.

## قاعدة البيانات ومصدر الحقيقة

تُحفظ الأقسام والأسعار والأصناف والوصفات والمخزون والمشتريات والجرد والصرف والمبيعات والورديات والمدفوعات والموظفون والحضور والإجازات والرواتب والمصاريف والإيرادات والمستخدمون والإعدادات وسجلات التدقيق في قاعدة PostgreSQL. تستخدم الواجهة `STATE` كذاكرة عرض مؤقتة فقط، ولا تُعد مصدرًا للبيانات.

تزامن شاشة الكاشير أقسامها لحظيًا من جدول `departments` إلى `pos_departments`. لذلك فإن إضافة أي قسم من شاشة الأقسام تجعله يظهر تلقائيًا في قائمة فتح وردية الكاشير، دون أسماء ثابتة داخل الواجهة.

## منيو الكاشير والمخزون

صنف الكاشير هو منتج بيع يتكون من الاسم والسعر والقسم والصورة والضريبة والوصفة عند الحاجة. لا توجد كمية مخزون يدوية في نموذج منيو الكاشير. الكمية والتوريد والجرد والحد الأدنى تُدار من المخزن، بينما تخصم المكونات من المخزن تلقائيًا عند بيع صنف مرتبط بوصفة. الصنف غير المرتبط بوصفة لا يُعتبر نافدًا بسبب قيمة POS صفرية.

## المبيعات والفواتير

يتم تسجيل البيع والمدفوعات والوردية وحركات المخزون والإيراد داخل معاملات آمنة. يمكن عرض الفاتورة وإعادة طباعتها من سجل الفواتير، كما يمكن إلغاء الفاتورة بصلاحية المدير أو مدير المطعم. الإلغاء يعكس المدفوعات كاسترجاع، ويعيد مكونات الوصفة إلى المخزن، ويسجل حركة عكسية وإيرادًا عكسيًا وسبب العملية.

## محرك المخزون العالمي

أضيف دفتر مخزون موحد في migration 021 عبر جدول `inventory_ledger`، وتُسجل فيه حركات opening balance وpurchase receipt وtransfer وsale consumption وproduction وwaste وreturn وcount correction وreversal. الأرصدة ليست مصدرًا تاريخيًا مستقلًا؛ بل projection مقفول من الدفتر، مع `on_hand` و`reserved` و`in_transit` و`quarantined` و`expired` لكل صنف وموقع. يمنع النظام الرصيد السالب افتراضيًا ويدعم idempotency وcorrelation context.

تدعم المواقع المتعددة المخزن الرئيسي وأقسام POS والمطبخ والإنتاج والمواقع المستقبلية. migration 022 تضيف دورة التحويل `requested → reserved → in_transit → received/reconciliation_required → reconciled` مع فصل الطلب والاعتماد والشحن والاستلام والتسوية، وسجل أحداث لا يُحذف. تعرض `/api/warehouse/intelligence/overview` لوحة مؤشرات PostgreSQL للرصيد المتاح والمحجوز، الأصناف الحرجة، التحويلات المفتوحة، فروقات الجرد، ومبيعات الأصناف اليومية.

## الوصفات والتكلفة التاريخية

تدعم migration 023 إصدارات الوصفات وBOM حسب `effective_from` و`effective_to`. يختار البيع إصدار الوصفة الفعال وقت العملية، لذلك لا يؤدي تعديل وصفة الغد إلى تغيير استهلاك مبيعات الأمس. يحافظ النظام على fallback للوصفات القديمة لضمان التوافق مع البيانات السابقة.

## الجرد وأذونات الصرف

يدعم النظام جردًا احترافيًا بمراحل مسودة وإرسال واعتماد وفروقات، مع قفل الصفوف والتحقق من تغير الرصيد قبل الاعتماد. أذونات الصرف تدعم العرض والموافقة والرفض، والموافقة الذرية تخصم المخزون وتسجل مصروف القسم وحركة المخزون داخل معاملة واحدة. الإرجاع يعكس العملية ويعيد الكمية إلى المخزن.

## التصفير الإنتاجي

التصفير الإنتاجي متاح للمدير فقط من الإعدادات. يتطلب عبارة التأكيد `CONFIRM PRODUCTION RESET` وسببًا لا يقل عن عشرة أحرف، ويرفض التنفيذ عند وجود وردية مفتوحة. يحذف السجلات التشغيلية والمالية ومستخدمي التشغيل والموظفين والمخزون والأصناف والمعاملات، ويحافظ على حساب المدير والإعدادات والأقسام المرجعية وسجل التدقيق. يجب أخذ نسخة PostgreSQL خارجية قبل التنفيذ.

## الهوية والطباعة

تم توحيد اسم **مطاعم الشرفة العالمية** والشعار في شاشة الدخول وواجهة ERP وPOS والتقارير وبطاقات الموظفين والفواتير. يتضمن مولد ESC/POS نسخة raster من الشعار، وتدعم الفواتير إعادة الطباعة من سجل المبيعات.

## التثبيت والتشغيل

انسخ `.env.example` إلى `.env`، واضبط اتصال PostgreSQL و`JWT_SECRET` ومفاتيح الطباعة وبيئة التشغيل. بعد ذلك نفّذ `npm install`، ثم شغّل `node scripts/setup.js` لتجهيز PostgreSQL وتطبيق migrations وترقية كلمة مرور bootstrap إلى bcrypt. شغّل النظام عبر `node backend/server.js` أو `npm start`، ثم افتح `/app/index.html`، وافتح شاشة الكاشير من `/pos/index.html`.

المستخدم الإداري الأول يُنشأ بواسطة migration 002 فقط، وتُنشأ الحسابات الأخرى من شاشة المستخدمين. لا تحتوي migrations الإنتاجية 002 و006 و012 على مخزون أو موظفين أو أصناف أو مبيعات أو مصاريف تجريبية. تُنشأ بيانات التشغيل من قاعدة البيانات عبر الواجهة والصلاحيات.

## الحوكمة وقابلية التدقيق

لا تعدل الحركات التاريخية ولا تُحذف معاملات المخزون أو التحويلات أو الاستلام أو التدقيق. الإلغاء والاسترجاع والجرد تستخدم حركات `reversal` أو `count_correction` داخل معاملات PostgreSQL، وكل تحويل يملك سجل أحداث للحالة والفاعل والسبب. هذا يجعل كل وحدة تنتقل من التوريد حتى الاستهلاك أو الإرجاع قابلة للتتبع.

## الأمان

تستخدم المصادقة JWT بصلاحية 24 ساعة، وتُحفظ كلمات المرور باستخدام bcrypt فقط. المسارات الحساسة محمية بصلاحيات الأدوار، وتستخدم عمليات البيع والجرد والصرف والاسترجاع والتصفير معاملات PostgreSQL وقفل الصفوف عند الحاجة. لا تُضمّن الحزمة `.env` أو قاعدة البيانات المحلية أو النسخ الاحتياطية أو `node_modules`.

## الاختبارات والمراجعة

نجحت فحوص صياغة ملفات الخادم والواجهة، ونجحت 9 مجموعات Jest بإجمالي **264 اختبارًا**. تم التحقق من صحة اتصال PostgreSQL، وبقاء حساب المدير والإعدادات، وخلو الجداول التشغيلية في قاعدة التسليم من بيانات الموظفين والرواتب والحضور والإيرادات والمصاريف والصرف والجرد والطلبات. أُزيلت أصناف الاختبار المكررة من قاعدة التشغيل قبل إنشاء الحزمة.

## محتويات الحزمة

تتضمن الحزمة المصدر الكامل، migrations، الواجهة، الخادم، الأصول والشعار، العمال الخلفيين، اختبارات المشروع، ملفات التشغيل على Windows، وملف `.env.example`. وتستبعد الأسرار، `node_modules`، `database/data`، `database/backups`، السجلات، والملفات المؤقتة.
