# محضر تسليم إنتاجي — مطاعم الشرفه العالمي ERP 3.1.1

## ملخص التسليم

هذه الحزمة هي إصدار **3.1.1** من مصدر نظام مطاعم الشرفه العالمي ERP، مهيأ لتشغيل خادم PostgreSQL محلي وخادم ERP على شبكة LAN، مع POS متجاوب، مخزون، مطبخ، موظفين، تقارير، دورة صرف موقعة، وجرد متعدد الفترات.

تم إغلاق العوائق التي ظهرت في تدقيق حزمة Clean: كلمة مرور الإدارة العامة، نموذج البيئة غير الآمن، ثغرات تشغيل Nodemailer وUUID، غياب lockfile، ربط خدمة Windows، وحماية الاستعادة التدميرية.

| المجال | حالة التسليم |
|---|---|
| اختبارات Jest | 273/273 ناجح |
| اختبار الاستجابة ومصدر PostgreSQL | ناجح |
| فحص اعتماديات Runtime | 0 ثغرات معروفة من npm audit |
| صياغة JavaScript للملفات المعدلة | ناجحة |
| بناء `dist` المصدر | ناجح |
| EXE/NSIS Windows فعلي | يحتاج البناء والاختبار على Windows |
| خدمة Windows والطباعة الفعلية | تحتاج اختبار قبول على جهاز Windows والطابعة |

## ضوابط الأمان الجديدة

لا تُنشأ كلمة مرور `admin/1234` في قاعدة جديدة. في أول تهيئة، يتحول مؤشر bootstrap إلى كلمة مرور عشوائية محلية، وتُحفظ بياناتها الأولية في ملف المستخدم المحلي المحمي، ثم يُلزم المسؤول بتغييرها قبل أي عمل تشغيلي. لا تشارك ملف البيانات الأولية ولا ترفعه إلى الشبكة أو أي خدمة تخزين عامة.

لا تحتوي الحزمة على `.env` فعلي أو قاعدة PostgreSQL محلية أو نسخ احتياطية. نموذج البيئة لا يحمل كلمة مرور قاعدة أو أسرار JWT أو API key قابلة للاستخدام، وتهيئة setup تولد القيم المحلية العشوائية. تحتوي الحزمة على `package-lock.json` لضمان تثبيت نسخ متكررة ومضبوطة من الاعتماديات.

تتطلب الاستعادة الآن تأكيدًا صريحًا باسم القاعدة، مثل:

```bat
node database\scripts\restore.js database\backups\backup.sql --confirm-drop=karim_erp
```

وقبل أي `DROP DATABASE` ينشئ النظام نسخة احتياطية تلقائية مع SHA-256 في مجلد النسخ الاحتياطية.

## تشغيل الخادم على Windows

ثبت Node.js 18 أو أحدث، ثم فك الحزمة في مجلد محلي، وافتح PowerShell أو Command Prompt داخل المجلد ونفذ:

```bat
npm ci --ignore-scripts
node scripts\karimabdelhamed.js setup
node scripts\karimabdelhamed.js start
```

بعد التشغيل، افتح على جهاز الخادم:

```text
http://localhost:5000/app/index.html
```

ومن هاتف أو جهاز آخر داخل نفس الشبكة افتح:

```text
http://SERVER_IP:5000/app/index.html
http://SERVER_IP:5000/app/pos.html
```

لا تستخدم `127.0.0.1` على الهاتف؛ فهو يشير إلى الهاتف نفسه. يجب أن يبقى PostgreSQL محليًا على الخادم، وألا يُفتح المنفذ 5432 للشبكة أو الإنترنت.

## بناء EXE وخدمة Windows

يُنفذ بناء EXE من جهاز Windows نظيف بعد تثبيت الاعتماديات:

```bat
npm ci
node scripts\karimabdelhamed.js build-exe
```

أصبح اسم Electron المتوقع `AlShorfaERP.exe`، وخدمة WinSW تستدعيه مع `--service`. بعد إنشاء Installer وتثبيته، تحقق من الآتي قبل الاعتماد التجاري:

| تحقق القبول | النتيجة المطلوبة |
|---|---|
| ملف التطبيق | وجود `AlShorfaERP.exe` داخل مسار التثبيت |
| الخدمة | ظهور `AlShorfaERP` بحالة Running في Windows Services |
| إعادة التشغيل | عودة الخدمة بعد reboot والوصول إلى `/api/health` |
| LAN | فتح لوحة الإدارة وPOS من هاتف على نفس الشبكة |
| الطباعة | طباعة فاتورة اختبار فعلية على الطابعة المستهدفة |

> لم يُدّعَ بناء EXE أو اختبار الخدمة والطباعة داخل Linux. هذه خطوة قبول إلزامية على Windows لأن NSIS وWinSW والطابعات تعتمد على نظام Windows الفعلي.

## فحوص الصيانة الموصى بها

شغّل هذه الأوامر قبل أي تحديث أو تسليم لاحق:

```bat
npm test
npm run responsive
npm audit --omit=dev
npm run build
```

اختبارات Smoke وIntegration وPOS وWorkflow تكتب في قاعدة الاختبار أو قاعدة مخصصة فقط، وتحتاج كلمة مرور اختبار عبر `KARIM_TEST_PASSWORD`. لا تشغّلها على قاعدة مطعم حية دون نسخة احتياطية وخطة استرجاع.

## قرار التسليم

حزمة المصدر مهيأة للتسليم اليوم بعد اجتياز فحوص الكود والبناء والاعتماديات. يبقى **اختبار قبول Windows الفعلي** شرطًا نهائيًا قبل إعلان EXE والخدمة والطباعة مجتازة، وهو شرط تشغيلي لا يمكن محاكاته بصدق داخل بيئة Linux.
