# تقرير إصلاح خطأ البيع في الكاشير

## السبب
كان استعلام مكونات الوصفة في مسار `POST /api/sales/complete` يقرأ العمود `rvi.product_id` من جدول `pos_recipe_version_ingredients`، بينما هذا الجدول يحتوي على `recipe_version_id` و`inventory_id` ولا يحتوي على `product_id`. لذلك كانت قاعدة البيانات تعيد الخطأ `column rvi.product_id does not exist`، وكانت الواجهة تعرض رسالة عامة: فشل إتمام البيع.

## الإصلاح
تم تعديل الاستعلام ليقرأ `rv.product_id` من جدول `pos_recipe_versions` المرتبط بإصدار الوصفة، مع إبقاء `rvi.inventory_id` وكمية المكون والوحدة من جدول المكونات.

كما تم تحسين تسجيل أخطاء البيع في الخادم ليحفظ الرسالة وكود PostgreSQL والجدول والعمود والقيد وStack Trace، حتى تظهر المشكلة في السجل بشكل قابل للتشخيص بدل فقدان التفاصيل.

## الاختبار الفعلي
تم فتح وردية لقسم البيع الخارجي، وتنفيذ بيع للصنف `ربع كبسه دجاج`، ثم تأكيد أن المعاملة اكتملت وأُنشئت الفاتورة وسجل الطباعة وقيد الإيراد.

| الحقل | النتيجة |
|---|---|
| رقم الطلب | `2da079f2-c12e-4ace-ac07-c437aec42e92` |
| رقم الفاتورة | `1` |
| الإجمالي | `17.25 SAR` |
| المدفوع | `17.25 SAR` |
| الباقي | `0 SAR` |
| مهمة الطباعة | `1` |
| حالة ZATCA | في الطابور |
| قيد إيراد القسم | تم إنشاؤه |

## التحقق النهائي
نجحت اختبارات Jest بعد الإصلاح: **264/264**. كما بقيت صحة API وقاعدة البيانات سليمة: `status=ok` و`database=healthy`.
