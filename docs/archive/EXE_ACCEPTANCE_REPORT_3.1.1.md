# تقرير قبول حزمة Windows 3.1.1

**النظام:** مطاعم الشرفه العالمي ERP  
**الإصدار:** 3.1.1  
**تاريخ التحقق:** 2026-08-24  
**نطاق الاختبار:** بيئات معزولة فقط؛ لم تُستخدم قاعدة المطعم أو بياناتها الحية.

## النتيجة المختصرة

تمت إعادة بناء ملفي Windows Setup وPortable من الشفرة المحدثة. اجتازت الترحيلات وتدوير كلمة المرور ومسار الدخول الأول في PostgreSQL وخادم HTTP معزولين. كما ثُبّت ملف Setup بصمت في Wine prefix نظيف وتحقق وجود الملفات التشغيلية المضمنة. مع ذلك، لا يُعد بدء PostgreSQL Windows من داخل Wine إثباتًا مقبولًا لتشغيله على Windows فعليًا؛ يلزم فحص قصير على جهاز Windows x64 نظيف قبل استخدام الحزمة على خادم المطعم.

| مجال التحقق | الإجراء | النتيجة |
|---|---|---|
| تهيئة قاعدة نظيفة | إنشاء عنقود PostgreSQL 16 محلي معزول، وإنشاء قاعدة اختبار، وتطبيق الترحيلات الإنتاجية | **نجح**: 31 ترحيلة؛ استُبعدت `006_demo_seed.sql` عمدًا |
| ترحيلة المطبخ | اختبار قاعدة فارغة كشف اعتمادًا مفقودًا في الترحيلة 030 ثم صُحح وأضيف اختبار انحدار | **نجح** |
| كلمة المسؤول | فحص bcrypt وعدم بقاء `1234` وفرض `must_change_password` | **نجح** دون كشف كلمة بدء أو hash |
| الدخول الأول | تسجيل دخول مقيد، منع مسار تشغيلي، تغيير كلمة المرور، ثم دخول طبيعي | **نجح** |
| اختبارات المشروع | Jest | **283/283 ناجحًا** |
| استجابة الواجهة | اختبار الاستجابة البنيوي وارتباط POS بمصدر PostgreSQL | **ناجح** |
| اعتماديات التشغيل | `npm audit --omit=dev` | **0 ثغرات تشغيلية معروفة** |
| بناء Windows | electron-builder عبر Wine prefix سليم | **نجح**: Setup وPortable |
| تثبيت Setup | تثبيت صامت في Wine prefix نظيف وفحص الموارد | **نجح**: التطبيق، PostgreSQL، الترحيلات، WinSW، والنسخ اليومي |

## ما شملته الحزمة المعاد بناؤها

يتضمن Setup وPortable ترحيلة `030_dispatch_signatures_audit_periods.sql` المصححة وترحيلة `032_first_login_password_rotation.sql`، وPostgreSQL runtime المضمن، وخدمة `AlShorfaERP`، وملف `DailyBackup.bat`، ومهمة النسخ اليومية التي يسجلها المثبت عند الساعة 02:00.

## القيد المتبقي والقبول المطلوب

واجه Wine توافقًا غير كافٍ مع `initdb.exe` الخاص بـ PostgreSQL Windows: ظهر خطأ تشغيل من طبقة Wine (`error 127`) رغم نجاح تثبيت Setup وفحص الملفات، ولذلك **لا يوجد ادعاء بأن خدمة Windows أنشأت القاعدة بنجاح على Windows حقيقي**.

> لا تثبّت مباشرة فوق بيانات المطعم. نفّذ القبول التالي أولًا على جهاز أو جهاز افتراضي Windows x64 نظيف ومسار اختبار منفصل.

| الخطوة على Windows الحقيقي | معيار النجاح |
|---|---|
| تشغيل Setup بصلاحية Administrator | اكتمال التثبيت دون رسالة خطأ |
| الانتظار حتى 90 ثانية | ظهور خدمة `AlShorfaERP` بحالة Running في Windows Services |
| فتح `http://localhost:5000/api/health` | `status: ok` وحالة قاعدة البيانات `healthy` |
| فتح ملف بيانات البدء المحلي | وجود `C:\ProgramData\AlShorfaERP\bootstrap-admin-credential.json` محليًا فقط |
| تسجيل الدخول الأول | مطالبة فورية بتغيير كلمة المرور وعدم السماح بالعمليات قبل ذلك |
| تشغيل مهمة النسخ الاحتياطي يدويًا مرة واحدة | ظهور ملف SQL وملف SHA-256 وسجل ناجح تحت `C:\ProgramData\AlShorfaERP\database\backups` |

بعد اجتياز هذه الخطوات يمكن نقل الإجراء نفسه إلى خادم المطعم وفق تعليمات `WINDOWS-EXE-FIRST-RUN-3.1.1.md`، مع إبقاء منفذ PostgreSQL محليًا وعدم فتحه للشبكة.
