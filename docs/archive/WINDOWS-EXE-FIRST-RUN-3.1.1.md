# تشغيل EXE — مطاعم الشرفه العالمي ERP 3.1.1

## اختر الملف المناسب

| الملف | الاستخدام |
|---|---|
| `Al-Shorfa-International-Restaurants-Setup-3.1.1.exe` | الخيار الموصى به للخادم الرئيسي. ثبّته بصلاحية Administrator؛ يسجل خدمة Windows لتشغيل قاعدة البيانات والخادم تلقائيًا. |
| `Al-Shorfa-International-Restaurants-Portable-3.1.1.exe` | تشغيل مباشر بالنقر المزدوج دون تثبيت. مناسب للتجربة أو جهاز خادم واحد، ويعمل طالما أن التطبيق مفتوح في الخلفية. |

## التشغيل الأول

1. على الخادم الرئيسي شغّل ملف **Setup** بزر الفأرة الأيمن ثم اختر **Run as administrator**.
2. أكمل التثبيت. يبدأ المثبت خدمة `AlShorfaERP` التي تنشئ PostgreSQL محليًا، تطبق الترحيلات الإنتاجية، وتدور كلمة المرور العامة إذا وجدت.
3. لا تغلق الجهاز أثناء أول تشغيل؛ قد يستغرق ذلك حتى 90 ثانية بسبب تهيئة قاعدة البيانات.
4. عند فتح التطبيق للمرة الأولى، استخدم بيانات المسؤول الأولية الموجودة في ملف:

```text
C:\ProgramData\AlShorfaERP\bootstrap-admin-credential.json
```

5. غيّر كلمة المرور فورًا عندما يطلب النظام ذلك، ثم احذف الملف أو احتفظ به في موقع آمن لا يراه الموظفون.

## الوصول من الشبكة المحلية

افتح لوحة الإدارة على الخادم:

```text
http://localhost:5000/app/index.html
```

ومن هاتف أو جهاز داخل نفس شبكة المطعم استخدم IP الخادم:

```text
http://SERVER_IP:5000/app/index.html
http://SERVER_IP:5000/app/pos.html
```

> لا تستخدم `127.0.0.1` أو `localhost` من الهاتف؛ كلاهما يشير إلى الهاتف نفسه.

## تحقق القبول بعد التثبيت

افتح **Windows Services** وتأكد من أن خدمة `AlShorfaERP` تعمل. ثم افتح `http://localhost:5000/api/health`؛ يجب أن تكون الحالة `ok` وقاعدة البيانات `healthy`.

لا تفتح منفذ PostgreSQL `5432` على الشبكة. اسمح فقط بمنفذ HTTP `5000` داخل شبكة LAN الموثوقة، وثبّت عنوان IP للخادم في الراوتر إن أمكن.

## النسخ الاحتياطي اليومي

بعد تثبيت ملف **Setup**، ينشئ المثبت تلقائيًا مهمة Windows باسم `AlShorfaERP-DailyBackup` تعمل يوميًا عند **02:00 صباحًا** بحساب النظام المحلي. لا تحتاج إلى فتح التطبيق أو إبقائه ظاهرًا.

تُحفظ النسخ في:

```text
C:\ProgramData\AlShorfaERP\database\backups
```

يُنشئ النظام ملف SQL وملف SHA-256 لكل نسخة، ويحتفظ بآخر **30 نسخة** فقط. ستجد آخر حالة في `daily-backup-status.json` وسجل التشغيل في:

```text
C:\ProgramData\AlShorfaERP\logs\daily-backup.log
```

يجب أن يكون مجلد النسخ متاحًا لـ Administrators وSYSTEM فقط. راجع من **Task Scheduler** أن حالة المهمة `Ready`، ثم استخدم **Run** مرة واحدة بعد التثبيت للتأكد من ظهور نسخة جديدة قبل انتظار موعد 02:00.

## حالة التحقق من الإصدار 3.1.1

أُعيد بناء ملفي Setup وPortable بعد إصلاح ترحيلة قاعدة البيانات النظيفة. تم تثبيت ملف Setup بصمت داخل Wine prefix نظيف بنجاح، وتحقق وجود التطبيق وموارد PostgreSQL المضمنة، وترحيلتي `030_dispatch_signatures_audit_periods.sql` و`032_first_login_password_rotation.sql`، وخدمة Windows وملف النسخ اليومي.

كما اجتاز اختبار قبول منفصل على PostgreSQL 16 معزول تطبيق **31 ترحيلة إنتاجية** (مع استبعاد `006_demo_seed.sql` عمدًا لعدم إنشاء بيانات تجريبية)، والتحقق من إنشاء المسؤول بكلمة bcrypt غير عامة، ووضع `must_change_password=true`. ثم أثبت اختبار HTTP معزول أن الرمز الأولي يمنع عمليات النظام حتى تغيير كلمة المرور، وأن تغييرها يفعّل تسجيل الدخول الطبيعي ورمز التحديث.

> **حد القبول المهم:** تثبيت Setup وفحص محتواه اجتازا تحت Wine، لكن تشغيل `initdb.exe` الخاص بـ PostgreSQL Windows داخل Wine فشل بسبب توافق Wine مع الملف التنفيذي (`error 127`). لذلك لا يُعد إنشاء قاعدة PostgreSQL وخدمة Windows من ملف EXE مثبتًا على Windows حقيقي حتى يُشغّل هذا الإجراء على جهاز Windows x64 نظيف. لا تُنشئ قاعدة جديدة فوق بيانات المطعم؛ نفّذ القبول على جهاز/مسار اختبار أولًا.
