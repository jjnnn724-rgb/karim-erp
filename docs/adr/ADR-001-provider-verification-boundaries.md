# ADR-001 — حدود المزوّدين وتصنيف الأدلة

- **الحالة:** مقترح — بانتظار اعتماد المالك
- **التاريخ:** 2026-11-10
- **النطاق:** كل مزوّد حكومي سعودي (ZATCA، مدد، التأمينات، قوى)

## السياق

البرنامج يتعامل مع جهات حكومية لا نملك لها وثائق رسمية مكتملة. أخطر خطأ ممكن
هو تحويل تخمين إلى «تكامل ناجح»: نداء إلى عنوان مُخترع، أو عرض استجابة محاكاة
كأنها قبول حكومي. GATE 01 صنّف الموجود: كود ZATCA موجود جزئيًا، الاعتماد
الإنتاجي غير مُثبت، مدد بلا واجهة برمجية عامة مُتحقَّق منها.

## القرار

1. **سجل مزوّدين في قاعدة البيانات** (`integration_providers`) يحمل لكل مزوّد:
   `verification`، `evidence_url`، `evidence_note`، `last_verified_at`،
   `is_enabled`. لا يُكرَّر التصنيف في الكود فقط.
2. **أربع حالات لا خامسة لها:**

   | الحالة | المعنى | يسمح بإرسال حقيقي؟ |
   |---|---|---|
   | `VERIFIED` | وثيقة رسمية مقروءة + تجربة مقبولة موثّقة بتاريخ | نعم، إن كان `is_enabled` |
   | `INFERRED` | سلوك مستنتج من كود قائم أو وثيقة غير كاملة | لا |
   | `UNVERIFIED` | افتراض بلا دليل كافٍ | لا |
   | `BLOCKED` | لا توجد واجهة/وثيقة متاحة أصلًا | لا |

3. **بوابة إرسال واحدة:** أي مسار يرسل إلى جهة حكومية يتحقق أولًا من
   `is_enabled = true` و`verification = 'VERIFIED'`، وإلا يرفض بـ
   `409 PROVIDER_NOT_VERIFIED` قبل أي اتصال شبكي.
4. **كل ادعاء يحمل تاريخًا.** لا عبارة «مدعوم» أو «متوافق» في كود أو وثيقة
   بلا `Last Verified` والمصدر.
5. **المحاكاة تُوسَم بثلاث طبقات:** حقل `sandbox=true` في استجابة مزوّد
   المحاكاة، وشارة صريحة في الواجهة، وسطر `outcome='success'` مع
   `metadata.simulated=true` في `integration_events`. لا تُحتسب محاكاة في
   تقارير الامتثال.
6. **التصنيف الابتدائي المعتمد في السجل:**

   | المزوّد | التصنيف | السبب |
   |---|---|---|
   | `zatca` | `UNVERIFIED` | كود الإعدادات والطابور موجود (VERIFIED كودًا)، لكن قبول الإنتاج غير مُثبت |
   | `mudad` | `BLOCKED` | لا واجهة برمجية عامة موثّقة |
   | `gosi` | `UNVERIFIED` | لا تكامل قائم ولا وثيقة أسرار |
   | `qiwa` | `UNVERIFIED` | لا تكامل قائم ولا وثيقة أسرار |

## العواقب

- لا يمكن «تشغيل» مزوّد بمجرد كتابة كود؛ يلزم دليل وتاريخ واعتماد مالك.
- الواجهة تعرض الحالة الحقيقية بدل إخفائها، فلا يوهم المشغّل بجاهزية غير قائمة.
- أي رفع لاحق للحالة يحتاج هجرة بيانات أو تحديثًا مُدقَّقًا، لا تعديل كود صامت.

## البدائل المرفوضة

- **تصنيف في متغيرات بيئة:** يتسرّب بين البيئات ويصعب تدقيقه.
- **`enabled` وحده بلا تصنيف:** يسمح بتشغيل مزوّد غير متحقق.
- **حذف مزوّد غير جاهز من الواجهة:** يخفي الحقيقة بدل إظهارها كمقيَّد.

## القيود المحفوظة

لا تغيير لعقود API قائمة، ولا لمس لمسارات `zatca-settings-routes.js` الحالية
في هذه المرحلة؛ السجل والجدول إضافة جديدة تُستهلك لاحقًا.
