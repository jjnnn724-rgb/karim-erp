# دليل معمارية السيرفر + عملاء الشبكة — Karim ERP

> **المبدأ:** قاعدة بيانات واحدة (PostgreSQL) — خادم واحد — كل الأجهزة تسمع لحظيًا.
> العميل EXE بلا قاعدة بيانات ولا خدمات: يفتح ويلاقي السيرفر لوحده على الشبكة.

```
                    ┌─────────────── PostgreSQL (المصدر الوحيد للحقيقة) ───────────────┐
                    │                                                                  │
                    │              SERVER EXE (جهاز الإدارة)                           │
                    │   PostgreSQL + API + واجهة كاملة كأدمن + إعلان الشبكة            │
                    │   + مجلد تحديثات الأجهزة (/updates)                              │
                    └───────────────┬──────────────────────────────────────────────────┘
                                    │  HTTPS :5000 (Socket.io لحظي)
              ┌─────────────────────┼─────────────────────┐
        CLIENT EXE              CLIENT EXE             CLIENT EXE
        (كاشير)                  (مطبخ)                 (HR)
   اكتشاف تلقائي UDP        اكتشاف تلقائي UDP      اكتشاف تلقائي UDP
```

---

## 1) جهاز السيرفر — التثبيت

1. ثبّت `KarimERP-Setup-x.y.z.exe` العادي (نفس المثبّت الحالي) وشغّله — هو السيرفر افتراضيًا.
2. من أيقونة الـ Tray بجوار الساعة تلاقي التحكم الكامل:
   - **نسخ رابط أجهزة الشبكة** — يعطيك العنوان (مثال `https://192.168.1.10:5000`).
   - **مجلد تحديثات الأجهزة (updates)** — يفتح مجلد التحديثات (شرح بالأسفل).
   - إظهار النافذة / فتح في المتصفح / إعادة تشغيل الخادم / خروج.
3. سجّل دخول كـ **admin** من التطبيق نفسه — الصلاحيات كاملة كما هي.

**إعلان الشبكة:** السيرفر يبث وجوده تلقائيًا على UDP 50505 كل 3 ثوانٍ،
ويرد فورًا على أي جهاز يسأل — لأجل هذا العملاء تلاقيه بلا إعدادات.
لتعطيله (نادرًا): `KARIM_LAN_BEACON=false`.

## 2) أجهزة العملاء — التثبيت

**الطريقة الأسهل (حزمة عميل جاهزة):**
```
npm run electron:build        ← يبني الإصدار المكتبي
npm run client:package        ← ينتج release/Karim-Client-<الإصدار>.zip
```
انسخ الملف المضغوط لأي جهاز، فك الضغط، وشغّل **Karim-Client.exe** — سيعرض
«جارٍ البحث عن الخادم…» ثم يتصل تلقائيًا ويفتح شاشة الدخول العادية.

**طريقة المثبّت الكامل (نفسه للطرفين):** ثبّت `KarimERP-Setup` عادي على جهاز
العميل، ثم ضع ملفًا اسمه `client-mode.json` (بإطار `{}` فارغ يكفي) في مجلد
التثبيت أو في `%APPDATA%\karim-erp\` وأعد فتح البرنامج.

**طريقة يدوية بالعنوان (لو الشبكة تمنع UDP):** ملف `server-target.json`:
```json
{ "serverUrl": "https://192.168.1.10:5000" }
```
العنوان اليدوي له الأولوية دائمًا على الاكتشاف التلقائي.

## 3) اللحظية بين الأجهزة

كل الأجهزة تتصل بـ Socket.io على السيرفر نفسه، والبيانات تتزامن فورًا:

- **القناة الحية (فورية):** بث الأحداث القديم — `sale:completed`,
  `entity_changed`, `biometric:punch` … (كما هي — صفر انحدار).
- **القناة الدائمة (Outbox):** كل حدث مالي/تشغيلي يُكتب في `event_outbox`
  داخل معاملة قاعدة البيانات نفسها، وناشر يبثه كل 500ms بـ SKIP LOCKED.
  العميل يتتبع رقم آخر حدث (`sequence`)، وعند أي انقطاع يستدعي
  `GET /api/rt/events?since=N` ليلحق ما فاته ثم يعمل ACK —
  **لا حدث يضيع حتى لو انقطعت الشبكة ساعات ورجعت.**
- **مؤشر الاتصال:** شارة أعلى الشاشة تُظهر حالة الاتصال + مصباح منفصل
  لقاعدة البيانات + قائمة الأجهزة المتصلة عند الضغط عليها.

## 4) تحديث أجهزة الشبكة من السيرفر (بلا إنترنت)

1. ابنِ الإصدار الجديد، ثم من جهاز السيرفر: افتح **Tray → مجلد تحديثات
   الأجهزة (updates)** وضع فيه:
   - `latest.yml` (يأتي مع مخرجات electron-builder في مجلد `release/`)
   - `KarimERP-Setup-x.y.z.exe` (حزمة التثبيت الجديدة)
2. كل عميل يفحص `{السيرفر}/updates/latest.yml` كل 10 دقائق، ينزّل التحديث
   ويثبّته عند الإغلاق — بدون تدخل ولا إنترنت.

> نصيحة: ثبّت شهادة `Karim-Local-CA.crt` على أجهزة العملاء (من السيرفر:
> `/app/Karim-Local-CA.crt`) — تريح متصفح Windows من تحذير mkcert وتؤمّن
> مسار التحديث عبر HTTPS.

## 5) الأمان (مطبق)

| الطبقة | التفصيل |
|---|---|
| الشبكة | HTTPS عبر شهادة mkcert؛ عميل EXE يقبل شهادة سيرفره **فقط** (مضيف مثبّت + مصدر mkcert) — لا تخفٍّ عام |
| الـ API | JWT + RBAC + x-api-key كما هي — العميل لا يلمس قاعدة البيانات إطلاقًا |
| السوكيت | JWT في المصافحة (خلف راية `RT_REQUIRE_AUTH`) + تسجيل الهوية من قاعدة البيانات |
| التحديث | العميل ينزّل من سيرفره هو فقط؛ شهادة CA عبر `NODE_EXTRA_CA_CERTS` |
| الفشل | فشل الاكتشاف/التحديث/الإعلان لا يُسقط أبدًا الخدمة الرئيسية |

## 6) استكشاف الأخطاء

| المشكلة | الحل |
|---|---|
| العميل عالق في «جارٍ البحث» | تأكد أن السيرفر شغّال وبنفس الشبكة؛ إن كان Firewall يمنع UDP 50505 اسمح له أو استخدم `server-target.json` |
| العميل يفتح لكن تحذير شهادة | ثبّت `Karim-Local-CA.crt` على العميل، أو استمر — العميل يقبل شهادة سيرفره المضبوط فقط |
| التحديث لا يصل للعملاء | تأكد من وجود `latest.yml` + حزمة `.exe` متطابقة الإصدار في مجلد updates |
| «سيرفر غير متاح» متكررة | السيرفر بيعيد الاتصال تلقائيًا (30 محاولة) — لو استمر: أعد تشغيل جهاز السيرفر |

## 7) الملفات التقنية (للمطوّر)

| ملف | الدور |
|---|---|
| `common/lan-discovery.js` | إعلان UDP + اكتشاف (مشترك للطرفين — وحدة نقية مُختبرة) |
| `electron/main.js` | وضع العميل (علامة/عنوان/اكتشاف) + نافذة بحث + تحديث LAN + قائمة Tray |
| `backend/server.js` | `GET /api/server/info` + خدمة مجلد `/updates` + بدء الإعلان |
| `frontend/app/js/realtime.js` | تتبّع sequence + resume/ack + تطبيق `SALE_POSTED` من Outbox |
| `scripts/make-client-package.js` | تجميع حزمة العميل (`npm run client:package`) |
| `tests/lan-discovery.test.js` | اختبارات الترميز/التحليل/الدورة الحية عبر UDP |
