# خريطة نظافة المستودع والتقييم الهيكلي — Karim ERP
**2026-11-19 · إعداد: تدقيق Hermes · الحالة:Production شغال — كل تغيير هنا لا يمس الإنتاج مباشرة**

## 1) رأي هندسي صريح: لماذا يبدو النظام «لخبطة»؟
الإحساس صحيح، وأسبابه بنيوية لا فوضوية:
1. **طبقتان تعيشان معًا:** ‏v2 القديم (`frontend/app`) ما زال يُخدم في الإنتاج، وv3 (`v3/`) هو المستقبل — نمط strangler سليم لكنه يعني ازدواجية مؤقتة في الملفات والمسارات.
2. **الخلفية monolith نامٍ:** ‏`backend/server.js` (~3200 سطر) يجمع الإقلاع والربط، ووحدات routes ضخمة (آلاف الأسطر). قابل للفهم لكنه ثقيل التنقل.
3. **هجين مديري حزم:** الجذر npm (`package-lock.json`) وv3 pnpm (`pnpm-workspace.yaml`) — حدودهما غير موثقة فتختلط الآثار (مثل `pnpm-lock.yaml` الدخيل بالجذر).
4. **طوبولوجيا worktree:** هذا المجلد worktree من نسخة أخرى على الجهاز، وأداة تطوير خارجية تحذف أحيانًا ملفات غير متتبعة — يزيد الإحساس بعدم الاستقرار.
5. **تراكم عضوي:** سكربتات لمرة واحدة، مستندات متقادمة، أجيال حزم قديمة، ومخرجات اختبار محلية.

**ما هو جيد فعلًا ولا يُمس:** الترحيلات append-only، اختبارات العقود، البوابات الحاجبة، فصل v3 النظيف (رموز/اختبارات/CI)، والتوثيق التشغيلي الحي.

## 2) قواعد التنظيف الملزمة (الإنتاج شغال)
- **لا حذف جماعي أبدًا لمسارات يخدمها الإنتاج:** ‏`backend/**`، `frontend/app/**`، `database/migrations/**`، `node_modules`.
- كل حذف بدليل (عدد مراجع = 0 عبر package.json/CI/docs/requires) وبإيداع git قابل للاسترجاع.
- غير المتتبع المشكوك فيه → **حجر** (مجلد quarantine خارج المسار المخدوم) لا محو.
- أجيال الحزم: يُحتفظ بجيلين بعد الحالي (تبويبات مفتوحة)؛ الأقدم يُقلّم بعد تحقق المراجع.
- الترحيلات لا تُحذف ولا تُعدّل تاريخيًا —.down فقط للموجود.

## 3) المراحل
### أ) الآن (هذه الجولة)
- جرد ملفات ميتة بالدليل (وكيل قراءة-فقط) → تنفيذ SAFE-REMOVE فقط، والباقي حجر/قرار مالك.
- تقليم أجيال `frontend/v3/assets` القديمة (بعد تحقق المراجع).
- تنظيف مخرجات محلية: ‏`test-results/`، نسخ تمارين DR المكررة (يُبقى دليل التمرين الموثق في RT_OPERATIONS).
- توثيق حدود مديري الحزم (الجذر npm / v3 pnpm) وإزالة الآثار الدخيلة.

### ب) التالي (أسابيع، بلا كسر)
- أرشفة السكربتات ميتة المرجع إلى `scripts/archive/` مع README يشرح الأصل.
- فصل إقلاع `server.js` عن الربط تدريجيًا (bootstrap module) بعقود الاختبارات القائمة.
- توحيد مكان التوثيق: ‏docs/ هو البيت؛ ما بالجذر يُنقل أو يُربط.
- إكمال ترحيل DataTable للشاشات غير المحدودة (انظر §4).

### ج) ربع سنوي (قرارات مالك)
- إتمام strangler: كل شاشة v2 تصل parity في v3 → إحالة ملفاتها للتقاعد شاشة-بشاشة بموافقة المالك.
- بنية إنتاجية عالية الإتاحة (replicas/failover/نسخ خارج الموقع) ومراقبة SLOs.
- اختبار اختراق مستقل واعتماد ZATCA.

## 5) ما لا يُنظف أبدًا بلا قرار مالك
- أي ملف في `frontend/app` (الإنتاج يخدمه) حتى لو بدا ميتًا.
- الترحيلات القديمة (تاريخ القاعدة).
- ‏`node_modules` (هجين npm/pnpm مستقر فعليًا؛ إعادة هيكلته مخاطرة بلا مكسب تشغيلي).
- سجلات التدقيق وقواعد البيانات إطلاقًا.
