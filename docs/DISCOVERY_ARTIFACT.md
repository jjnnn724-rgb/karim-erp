## 4. الوقت الحقيقي (المكتشف — الأهم للعقد)

موجود فعليًا ويعمل:
- `server.js`: `io.on('connection')` — تسجيل مستخدم/جهاز، `clients_list`, `device_connected/disconnected`, `ping/pong_check`, `sync_data`, `state_updated`, `entity_changed`, غرف `user:<id>` و `dept:<code>`, إشعارات، شات.
- أحداث بيع: `complete-sale.js` يبث `sale:completed` (غرفة قسم + بث عام) + `state_updated` بعد الالتزام.
- ياراسوفت: `oracle-link.js` استطلاع كل دقيقة (env) → `yarasoft:oracle-sync` + `yarasoft:imported` → الواجهة تسمع فورًا.
- الواجهة: `realtime.js` — Socket.IO client مع إعادة اتصال تدريجية (MAX_RECONNECT)، سباق تحديث وحيد `isSyncing`, سماع كل الأحداث أعلاه + لوحة كاشيرات حية تُحدَّث كل 30 ثانية.

**الخلاصة المعمارية**: البنية المطالَبة في التوجيه (WebSocket delivery + recovery + idempotency + outbox) يجب أن تُبنى **كامتداد** لهذا الواقع (LAW 07: REUSE → EXTEND) وليس استبدالًا — الاستبدال يخالف LAW 02 (Zero Regression).

## 5. الديون المعمارية المكتشفة (ما يعالجه التوجيه)

1. **لا يوجد Transactional Outbox**: البث الحالي يتم بعد الالتزام بـ try/catch منفصل — تعطل العملية بين COMMIT والبث يفقد الحدث (لا recovery).
2. **لا يوجد تسلسل عالمي للأحداث** ولا ACK لكل عميل ولا نقطة استعادة `GET /api/rt/events`.
3. **لا توجد envelope موحدة** — كل حدث شكله خاص (state_updated/sale:completed/...).
4. **البث عام غير مُرشّح صلاحياتيًا** (`io.emit`) — عزل الفروع/الأقسام على أحداث الوقت الحقيقي غير مفروض على مستوى التوجيه.
5. **Idempotency جزئي**: ممتاز في POS؛ غائب عن بقية العمليات الحرجة (أذون الصرف، التحويلات، القيود).
6. **لا يوجد LAN Update Control Plane**: تحديث العميل يدوي (بناء EXE وتثبيت يدوي).
7. Polling متبقٍ: لوحة الكاشيرات (30 ث) — مبرر كـ fallback وفق LAW 38.

## 6. مخاطر التغيير الحرجة (خرائط عدم الكسر)

- `server.js` ملف أحجام ضخمة (~1800 سطر) بترتيب تسجيل حساس — أي تعديل يكون إلحاق/تسجيل راوتر جديد فقط.
- إنشاء الجداول عبر ترحيلات مرقّمة فقط (`run-migration.js`) — ممنوع DDL يدوي.
- إعادة تشغيل السيرفر مطلوبة لأي تغيير خلفية — توقيت النافذة مسؤولية المشغل.
- PostgreSQL لا يستقبل اتصالات خارج الآلة (pg_hba) — كل تشغيل اختباري/نسخ DB يتم على آلة السيرفر.
- `emitEntityChange`/`emit` في CRUD العام يغذي الواجهة بالكامل — لا يجوز تغيير توقيعاتها.
