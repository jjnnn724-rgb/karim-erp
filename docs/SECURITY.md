# 🔐 سياسة الأمان — karim ERP LAN Edition

هذا المستند يوضّح نموذج التهديد الذي صُمم النظام على أساسه، والقيود الأمنية الواجب مراعاتها، وكيفية تشديد الحماية عند الحاجة.

## 1. نموذج التهديد

النظام مصمَّم ليعمل **داخل شبكة محلية موثوقة (Trusted LAN)** مثل شبكة مطعم أو فندق. لا يُفترض أبداً تعريضه للإنترنت العام دون إضافة طبقات حماية إضافية.

| التهديد | الحماية المتوفرة | ملاحظة |
|---|---|---|
| اعتراض البيانات على الشبكة | غير مشفّر (HTTP) | مقبول على LAN الموثوقة. للإنترنت استخدم HTTPS + reverse proxy. |
| وصول عميل غير مصرح للـ API | اختياري عبر `API_KEY` | اضبط `API_KEY` في `.env` ليُطلب من كل عميل إرسال `x-api-key`. |
| حقن SQL عبر الأعمدة | محجوب | جميع الأعمدة يتم التحقق منها مقابل `information_schema.columns` قبل البناء. |
| حقن SQL عبر القيم | محجوب | جميع القيم تُمرّر عبر `$1, $2, ...` (parameterized queries). |
| تعرّض كلمة المرور على الشبكة | غير مشفّر | اقبل فقط على LAN الموثوقة. |
| تخزين كلمات المرور | نص صريح | قرار منتج. للترقية استخدم `pgcrypto` (انظر أدناه). |
| فيضان الطلبات (DoS) | `STATEMENT_TIMEOUT_MS` + حدود حجم الحمولة | للحدّ الأقصى استخدم rate-limiter مثل `express-rate-limit`. |
| تعرّض بيانات الجلسة | يتم تجريد `currentUser` قبل حفظ STATE | لا تُشارك بين الأجهزة. |

## 2. إعداد أكثر أماناً (موصى به للإنتاج)

1. **ضبط كلمة مرور لقاعدة البيانات** قبل أول تشغيل:
   ```bash
   # في ملف .env
   DB_PASSWORD=كلمة_مرور_قوية_جداً
   ```
   عند أول تشغيل لـ `start-pg.js` سيتم تهيئة PostgreSQL مع `scram-sha-256` وستُضبط كلمة المرور على دور `postgres`.

2. **تفعيل مفتاح API**:
   ```bash
   # في ملف .env
   API_KEY=سلسلة_عشوائية_طويلة
   ```
   سيُطلب من كل عميل إرسال `x-api-key: <value>` مع كل طلب. الواجهة الأمامية تقرأ المفتاح تلقائياً من `localStorage['gv_api_key']`.

3. **تقييد `pg_hba.conf`**:
   السكربت يكتب قواعد تسمح فقط لشبكات LAN الخاصة (10/8, 172.16/12, 192.168/16, localhost). لا يُسمح بـ `0.0.0.0/0`.

4. **جدار الحماية**: افتح المنفذ `5000` فقط على واجهة LAN.

## 3. ترقية كلمات المرور إلى تشفير (pgcrypto)

إذا قررت لاحقاً تشفير كلمات المرور:

```sql
-- 1) تفعيل الإضافة
CREATE EXTENSION IF NOT EXISTS pgcrypto;

-- 2) إضافة عمود للهاش
ALTER TABLE users ADD COLUMN IF NOT EXISTS password_hash TEXT;

-- 3) تحويل كلمات المرور الحالية
UPDATE users SET password_hash = crypt(password, gen_salt('bf'))
WHERE password_hash IS NULL;

-- 4) بعد التحقق من عمل التطبيق، احذف العمود القديم
ALTER TABLE users DROP COLUMN password;
```

ثم عدّل دالة تسجيل الدخول في الواجهة الأمامية لتُرسل كلمة المرور كنص صريح (سيتم تشفيرها في الخادم عبر `crypt($1, password_hash) = password_hash`).

## 4. ما يجب ألا تفعله

- ❌ **لا** تستخدم `ngrok` أو أي نفق عام دون تفعيل `API_KEY` و HTTPS.
- ❌ **لا** تترك `DB_PASSWORD=` فارغة على جهاز متصل بشبكة Wi-Fi عامة.
- ❌ **لا** تشارك ملف `.env` بين الموظفين عبر البريد أو مواقع الدردشة.
- ❌ **لا** تنشر مجلد `database/data/` — يحتوي على كل بيانات المطعم.

## 5. الإبلاغ عن ثغرات

إذا اكتشفت ثغرة، أبلغ فريق التطوير الداخلي. لا تنشر تفاصيلها في قنوات عامة حتى يتم إصلاحها.
