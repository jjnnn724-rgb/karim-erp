# تشغيل نظام حورس ERP على aaPanel

هذه الحزمة مخصصة لخادم Linux/VPS يعمل عليه aaPanel. تستخدم PostgreSQL المثبت على الخادم، وNode.js، وPM2، وNginx. لا تستخدم PostgreSQL Windows المضمن في ملفات EXE، ولا تحتوي على ملف `.env` أو كلمة مرور جاهزة أو بيانات مبيعات تجريبية.

## المتطلبات

ثبّت من aaPanel أو من مدير النظام إصدار Node.js 20 أو أحدث، وPostgreSQL 14 أو أحدث، وNginx، وGit أو أداة رفع الملفات. يجب أن يكون الخادم قادرًا على تشغيل Node.js بذاكرة مناسبة للإنتاج، وأن يكون منفذ PostgreSQL محليًا فقط. لا تفتح المنفذ 5432 في جدار الحماية.

## رفع المشروع

ارفع محتويات المشروع إلى مسار مستقل، مثل `/www/wwwroot/karim-erp`. احتفظ بمجلد `deploy/aapanel` داخل المشروع؛ لا ترفع ملفات `release/*.exe` إلى موقع الويب، لأنها تخص Windows فقط. بعد الرفع نفّذ:

```bash
cd /www/wwwroot/karim-erp
chmod +x deploy/aapanel/install-aapanel.sh deploy/aapanel/update-aapanel.sh
```

## التهيئة الأولى

شغّل السكربت التالي مرة واحدة بصلاحية root. ينشئ مستخدم PostgreSQL وقاعدة `karim_erp` عند عدم وجودهما، يولد الأسرار محليًا، يثبت اعتماديات الخادم، يطبق الترحيلات من 001 إلى 032 باستثناء `006_demo_seed.sql`، ثم يبدأ PM2. لا يحذف قاعدة موجودة ولا ينفذ reset.

```bash
sudo APP_DIR=/www/wwwroot/karim-erp bash deploy/aapanel/install-aapanel.sh
```

يُنشئ السكربت ملف `.env` بصلاحية 640، وملف `.aapanel-runtime-user` بصلاحية 600، وملف بيانات المسؤول الأولية داخل `.aapanel-bootstrap` بصلاحية 700/600. يستخدم `APP_USER=www` افتراضيًا، وإذا لم يكن موجودًا ينشئ مستخدم نظام مقيدًا باسم `karim-erp`؛ لا يعود تلقائيًا إلى تشغيل التطبيق بصلاحية root. إذا أردت مستخدمًا خاصًا مسبقًا، مرّر مثلًا `APP_USER=karim` بشرط أن يكون موجودًا وغير root. كود التطبيق و`node_modules` مملوكان لـ root وقابلان للقراءة فقط من مجموعة مستخدم الخدمة، بينما تقتصر الكتابة على مجلدات التشغيل. سجّل الدخول ببيانات البدء محليًا، غيّر كلمة المرور فورًا، ثم انقل الملف إلى مكان آمن أو احذفه. لا ترسل الملف عبر البريد أو تضعه داخل مجلد عام.

## ربط النطاق عبر aaPanel

أنشئ موقع Node.js أو موقع Proxy في aaPanel، واجعل Nginx يمرر الطلبات إلى `127.0.0.1:5000`. انسخ محتوى `nginx-karim.conf.template` إلى إعدادات الموقع، ثم أصدر شهادة SSL من aaPanel. عدّل `ALLOWED_ORIGINS` داخل `.env` إلى عنوان HTTPS الفعلي، ثم نفّذ إعادة التشغيل عبر الخدمة:

```bash
cd /www/wwwroot/karim-erp
sudo systemctl restart karim-erp.service
```

إذا لم يتوفر systemd في إعداد aaPanel، استخدم PM2 تحت مستخدم الخدمة نفسه، وليس root: `sudo -u www pm2 restart karim-erp --update-env`.

لا تستخدم `http://localhost:5000` أو `127.0.0.1` من هاتف أو جهاز خارجي؛ استخدم نطاق HTTPS أو عنوان الخادم المسموح به. لا تجعل Node.js أو PostgreSQL مكشوفين للإنترنت مباشرة.

## التحقق

تحقق من الخدمة والعمليات:

```bash
pm2 status
pm2 logs karim-erp --lines 100
curl -fsS http://127.0.0.1:5000/api/health
```

يجب أن تعيد health حالة `ok` وأن تكون قاعدة البيانات `healthy`. إذا ظهر `degraded`، راجع اتصال PostgreSQL وملف `.env` قبل إعادة تشغيل التطبيق.

## التحديثات

خذ نسخة PostgreSQL احتياطية خارج مسار التطبيق قبل كل تحديث. ارفع ملفات الإصدار الجديد فوق نسخة الكود مع الاحتفاظ بـ `.env` ومجلدي `database/media` و`database/backups`، ثم نفّذ:

```bash
sudo APP_DIR=/www/wwwroot/karim-erp bash deploy/aapanel/update-aapanel.sh
```

يطبق السكربت الترحيلات بصورة متسلسلة ويعيد تشغيل PM2. لا تشغّل `reset` ولا تحذف قاعدة البيانات أثناء التحديث.

## النسخ الاحتياطي

يمكن جدولة نسخة PostgreSQL عبر Cron في aaPanel، مثلًا مرة يوميًا عند 02:00، باستخدام سكربت `database/scripts/backup.js` بعد ضبط `.env` ومسار النسخ. يفضل حفظ النسخ على قرص أو مخزن خارجي، وليس داخل نفس القرص الوحيد للخادم. اختبر الاستعادة على قاعدة منفصلة؛ لا تستعد فوق قاعدة الإنتاج مباشرة.

## ملاحظات أمنية

لا تضع قيم `JWT_SECRET` أو `DB_PASSWORD` أو `API_KEY` في Git أو داخل ملف ZIP العام. حدّد صلاحيات `.env` إلى 640 (root مع مجموعة مستخدم الخدمة) حتى يستطيع التطبيق قراءته دون أن يكون مكشوفًا للعامة، واجعل ملفات النسخ وبيانات البدء متاحة للحساب الإداري فقط. لا تستخدم صلاحيات مفتوحة مثل `777`؛ كود التطبيق للقراءة فقط، والكتابة محصورة في `logs` و`database/media` و`database/backups`. استخدم HTTPS، وفعّل جدار الحماية للسماح بـ 80/443 وSSH من عناوين موثوقة فقط. لا تستخدم بيانات `admin/1234`؛ الإصدار الحالي يولد كلمة أولية عشوائية ويفرض تدويرها عند أول دخول.

## حدود هذه الحزمة

هذه تعليمات تشغيل على aaPanel/Linux وليست نشرًا تلقائيًا على حسابك؛ لا تحتوي على بيانات دخول VPS أو aaPanel أو نطاق. يجب أن ينفذ مسؤول الخادم الخطوات على VPS الخاص به، ثم يرسل نتيجة `/api/health` وسجل PM2 عند الحاجة إلى تشخيص إضافي.
