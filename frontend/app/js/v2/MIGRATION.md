# V2 — سجل الترحيل (صفحة-صفحة، بنظام)
> الوثيقة الحاكمة لنقل الشاشات إلى V2. أي شاشة جديدة تُنقل بهذا العقد أو لا تُنقل.

## القواعد الثابتة (اتفاق المالك)
1. **منظّم**: كل شاشة لها رقم وسطر في الجدول أدناه — لا عمل خارج السجل.
2. **ثابت عالمي + الميكس الساحر**: لغة التصميم مجمّدة (Fiori هيكل + Odoo روح +
   NetSuite كثافة + لوحة أوامر + هوية بيضاء + عربي RTL أولًا). أي شاشة جديدة
   تستخدم نفس المكوّنات (EnterpriseDataTable + status adapter + شرائح KPI +
   عناوين ثنائية) — لا لغة تصميم جديدة لكل شاشة.
3. **صفحة-صفحة باحترافية**: شاشة واحدة تُكمل وتُتحقق وتُعتمد قبل التالية.
   صفر تعديل على legacy، صفر تعديل على الباك-إند، الرجوع = حذف مجلد V2.

## عقد الشاشة الواحدة (يُطبق حرفيًا)
- القراءة أولًا: الشاشة الجديدة تبدأ قراءة فقط (لا POST/PUT/DELETE في ملفاتها).
- باب واحد للشبكة: `js/v2/data/<name>-repo.js` (العقد منقول من ملف الباك-إند
  نفسه، مذكورًا برقم السطر) + `js/v2/screens/<name>.js` (عرض فقط).
- دوال التحويل pure ومصدّرة (attendanceToRow/branchToRow) — قابلة للاختبار
  بدون متصفح.
- لا قيم مخترعة: القيم المحفوظة عبر status adapter، المشتقة كنقاط + نص،
  المجهول يُعرض خامًا — أبدًا تخمين.
- الوضع غير الحيّ لا يعرض بيانات مزيّفة باسم الشاشة (يُحيل لعينة اللوحة
  المعلنة أو يقول "لا جلسة — لا عرض").
- حراس التحميل/الحفظ + فحص `isConnected` قبل لمس DOM + `destroy()` يزيل
  المستمعات — نسخة واحدة حيّة في كل لحظة (teardown عند التنقل).
- نسخة صفحة موحدة (درس 2026-10-14): كل `?v=` في v2.html وكل `from '...'`
  نسبي في js/v2/** يحمل قيمة واحدة — هي قيمة وسم preview.js. اختبارات
  v2-branches وv2-briefing وv2-reports تفرض ذلك نصًا. ممنوع نسخ ملفية
  منفصلة (كانت سبب stale صامت خلف كاش Cloudflare).
